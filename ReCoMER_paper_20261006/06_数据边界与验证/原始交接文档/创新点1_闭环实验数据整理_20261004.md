# 创新点 1：闭环融合架构实验数据整理

更新时间：2026-10-04  
数据来源：A100 node243 服务器上的已完成实验、当前 `n6` 源码和本地交接文档。  
本报告只整理已有结果，不新增训练，不读取 test split。

## 1. 结论先行

当前证据支持的结论是：**历史反馈在部分数据条件下有用，但尚未证明“闭环顺序”本身优于前面加或后面加。**

当前 `utility=uniform` 的赢家配置更准确的描述是“历史条件残差融合”，而不是完整意义上的“反馈后再判断闭环”。原因是：

1. 历史注入后进入每个模态的线性 solo head；
2. `utility=uniform` 时最终模态权重固定为 `1/3`，没有第二次动态模态判断；
3. Transformer joint head 参与辅助 KL，但不是实际部署输出；
4. 因此历史注入可以代数地重排为输出端的历史 logit 残差。

## 5. 代码层机制解释

当前历史池化位于 [代码/创新点1_闭环对照/code/n6/model.py](../代码/创新点1_闭环对照/code/n6/model.py) 的 `HistoryAttnPool`：

```text
p_m = HistoryAttention(e_m, history_m)
e'_m = e_m + gamma_m * p_m
z'_m = Linear(e'_m)
output = mean(z'_T, z'_A, z'_V)   # utility=uniform
```

因为 `Linear` 是线性的，当前路径满足：

```text
mean(Linear(e_m + gamma_m * p_m))
= mean(Linear(e_m)) + mean(Linear(gamma_m * p_m))
```

因此，在均匀权重配置下，前面注入历史与在输出端加入对应历史残差可以落在同一表示空间。真正的闭环需要反馈后的状态进入非线性部署决策，或者让反馈后产生样本级的模态/历史准入变化。

此外，当前 `HistoryAttnPool.gamma` 是每个模态一个全局标量，而不是每个样本的历史强度。历史注意力可以逐句选择槽位，但反馈幅度不能逐句决定，这也是翻转句容易被历史拖累的原因。

## 6. 创新点 3 当前实现的阻塞问题

弃权代码先把空候选加入 softmax，再删除空候选并重新归一化历史槽权重。这样会把空候选质量重新分配给剩余历史，不能真正实现“整体拒绝历史”。

只读检查结果：

- M3ED 空候选概率约 0.25；
- MELD 空候选概率约 0.44–0.45；
- 但删除空候选后，历史槽注意力与不带空候选的结果最大差异约为 `1e-7`；
- 因此模型虽然学到了“应该拒绝”的概率，反馈通道却没有按该概率减弱。

应改为保留历史槽的原始总质量，使历史反馈实际乘以 `1 - p_null`；或者使用等价的显式句级历史增益门。修复后需要先做单 batch 数学单元测试，再做 MELD 小规模训练和十 seed 验收。

## 8. 创新点 1 后续验收条件

等创新点 3 修复后，按以下顺序执行：

1. 验证空候选质量真的降低历史反馈强度；
2. 在 MELD 上重测延续句与翻转句；
3. 保留当前 `uniform_h` 作为历史反馈基线；
4. 实现参数量和历史读取器匹配的前加、后加、闭环三臂；
5. 若要继续使用“闭环”命名，让反馈后的状态进入实际部署的非线性再判断模块；
6. 十 seed 配对 CI 不含 0、至少 8/10 同向，并在独立上下文数据上复现；
7. 在这些条件满足前，论文表述使用“条件性历史反馈融合”，不要声称已证明闭环顺序优于前加或后加。
