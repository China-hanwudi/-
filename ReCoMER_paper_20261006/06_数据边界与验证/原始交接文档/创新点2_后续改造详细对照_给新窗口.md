# 创新点二：后续统一改造说明（给新窗口）

> 本文只说明创新点二。创新点一、三尚未改好，不能把它们的代码、参数或训练目标提前并入创新点二。
> 本文是后续“三个创新点一起改”时的实施依据；本轮不修改任何模型代码和检查点。

## 1. 先给结论

创新点二不要再使用“自由门控 + 任务损失直接反向更新门控”的原始方案。后续建议以以下结构作为统一候选：

```text
冻结/正常训练的模态编码器、solo head、joint head
        ↓
每个模态的表征 + solo 预测 + 模态可用性/不确定性证据
        ↓
EvidenceRouter（模态局部分支 + 共享跨模态上下文）
        ↓
预测三个模态的贡献分数 mu
        ↓
原有中心化 bounded 权重公式（lambda=0.3）
        ↓
solo logits 加权融合
```

必须保持不变的三件事：

1. 原有逐样本、七个非空子集的精确 Shapley 测量；
2. 原有贡献分数中心化；
3. 原有 bounded 权重及其 `lambda=0.3`，包括缺失模态时的重归一化规则。

当前最适合作为“统一默认门控”的是 `EvidenceRouter + evidence_task`：它在 MOSEI 上有最稳定证据，也比原 MLP 门控更稳定。但不能把它描述成所有数据集的最优门控：M3ED 原始 E2 表征上仍然负增益，MELD 上普通 MLP 有时略优。

## 2. 原始版本是什么

原始创新点二的门控主体是 `UtilityHead`，位置为：

```text
代码/00_原始代码/code/n6/model.py
```

其主要逻辑是：

```text
三个模态 embedding 拼接
+ 三个两两余弦相似度
+ 三个 solo confidence
        ↓
一个共享 MLP
        ↓
三个 utility score
        ↓
softmax（旧自由门控）或 bounded 权重
        ↓
solo logits 加权
```

原始 `UtilityHead` 的问题不是“有没有 Shapley”，而是门控网络可以从混合后的高维输入中学习一个任务捷径。它容易出现以下行为：

- 直接偏向训练集上平均更强的模态，而不是按当前样本的真实贡献分配权重；
- 在强表征（尤其 E2 音频）存在时，某一模态长期占主导；
- 把“模态之间相似”误认为“各模态都可靠”；
- 把预测分歧当成错误信号，可能压低真正包含少数但重要信息的模态；
- 自由 softmax 门控容易产生过度尖锐的权重，导致一个模态几乎控制最终结果；
- 任务损失直接穿过部署权重更新门控时，门控会追求当前验证任务，而不再忠实近似 Shapley 贡献。

因此，原始方案的核心问题是“门控输入和门控目标没有把模态局部证据、跨模态关系、Shapley 教师和最终任务收益分开”。

## 3. 当前改造版改了什么

当前实现位于：

```text
代码/创新点2_门控对照/code/n6/
```

### 3.1 新增 `EvidenceRouter`

`model.py` 中新增了 `EvidenceRouter`，它不再把所有模态直接混成一个黑盒 MLP，而是分三步：

1. 每个模态单独经过 `LayerNorm → Linear(d_model,48) → GELU`；
2. 计算可解释的证据：
   - 分类：每个模态的类别概率、最大概率、熵、top-1/top-2 margin、logit scale、与平均预测的分歧、是否与共识类别一致、模态是否存在；
   - 回归：每个模态预测、相对均值偏差、绝对偏差、预测 spread、两两预测差异、缺失标记；
3. 将模态局部表示、共享上下文、局部-上下文差异和预测证据送入共享评分器，输出每个模态一个 `mu`。

这一步的设计目的，是让门控先回答“这个模态自身是否有证据”，再回答“它相对于其他模态是否有用”，避免只根据全局平均偏好选模态。

### 3.2 新增门控分支，但不改变部署公式

`config.py` 增加了：

```text
gate_architecture = legacy | evidence | constant
gate_detach_inputs
detach_utility_path
utility_head_version
```

对应关系：

- `legacy`：旧 `UtilityHead`，仅作为对照；
- `evidence`：当前 `EvidenceRouter`；
- `constant`：固定模态偏好，用于排除“只学会固定权重”的可能性。

`deploy_weights()` 仍然是原来的部署入口。当前新门控只改变 `mu` 的来源，不改变 `mu` 如何变成最终权重。

### 3.3 新增门控专用训练入口

`train_gate.py` 的流程是：

1. 读取已训练的 uniform checkpoint；
2. 冻结编码器、历史模块、solo head、joint head；
3. 在固定训练底座上计算逐样本 Shapley 教师；
4. 只更新 `utility_head`；
5. 验证集只用于任务指标选择和 SWA(3)，不计算验证 Shapley，不读取测试集；
6. 训练完成后检查完整 forward 是否复现保存的验证指标。

当前 `evidence_task` 的门控目标为：

```text
任务损失 + 0.3 × Shapley MSE + 0.1 × Shapley 排序损失
```

其中任务梯度只能更新门控参数，不能更新底座。这样做的动机是让门控不仅拟合 Shapley，还要对最终预测有用；但它也带来“任务收益和 Shapley 忠实度冲突”的风险，后续必须单独报告二者，不能只报告其中一个。

### 3.4 增加加载、掩码和审计保护

当前版本还增加了：

- 旧 checkpoint 的 utility head 兼容加载；
- 缺失模态掩码与权重重归一化；
- `train.pt/valid.pt` 白名单读取，测试集文件名直接拒绝；
- frozen base 检查，确保门控实验没有偷偷改变底座；
- Shapley 与 `deploy_weights` 的 AST 一致性检查；
- 检查点保存 `RUN_METADATA.json`，记录门控目标、种子、底座哈希和测试集未读取状态。

## 4. 哪些尝试不是最终方案

以下代码或变体可以保留作历史对照，但不能在新窗口里误当成最终创新点二：

- `ContributionGate`：早期“局部贡献 + context”尝试；保留了 `rich` 分支和 sigma 接口，但没有作为最终统一默认；
- `constant_task`：固定偏好控制，不是创新方案；
- `mlp_task`：旧 MLP 的任务校准对照；
- `evidence`：只做 Shapley MSE 的证据门控；
- `evidence_rank`：证据门控加排序损失，但没有任务校准；
- `evidence_task`：当前最适合做统一默认的候选。

新窗口不得直接把 `ContributionGate`、`evidence_task`、创新点一的门控或创新点三的弃权逻辑拼接在一起。必须先统一配置字段、前向顺序和损失归属。

## 5. 实验结果说明“有效”到什么程度

### 5.1 主表征、10 个训练种子

固定底座、固定验证集、只改变门控：

| 数据集 | 主要指标 | uniform | evidence_task | 结果 |
|---|---:|---:|---:|---:|
| MOSEI | MAE↓ | 0.56613 | 0.55939 | 平均降低 0.00674，10/10 改善 |
| MELD | weighted F1↑ | 57.77% | 58.11% | 平均 +0.34 个百分点，8/10 改善 |
| M3ED | weighted F1↑ | 60.21% | 59.88% | 平均 −0.33 个百分点，2/10 改善 |

因此当前最可靠的表述是：

> 改进门控在 MOSEI 验证集回归 MAE 上具有稳定收益，在 MELD 上有中等收益，但在当前 M3ED E2 表征上未形成跨数据集稳定收益。

不能写成“创新点二在所有数据集和所有指标上有效”。

### 5.2 强表征和新增数据集：只作方向性证据

当前三种子初筛结果：

| 配置 | uniform | evidence_task | 解释 |
|---|---:|---:|---|
| MOSEI full 强表征 MAE | 0.50428 | 0.50255 | 小幅改善，样本数不足以定论 |
| MELD RoBERTa weighted F1 | 64.28% | 63.98% | 强表征不等于门控一定有效 |
| M3ED RoBERTa weighted F1 | 54.27% | 54.63% | 换表征后方向变正，但整体低于 E2 表征 |
| CMU-MOSI MAE | 0.71693 | 0.71089 | 方向为正，仍需更多种子 |
| CH-SIMS v2 MAE | 0.33651 | 0.33211 | 三个种子均改善，仍属于初筛 |

表征收益和门控收益必须分开归因：先比较同一表征下 uniform 与新门控，再比较不同表征下 uniform 与 uniform。不能把换表征带来的提升写成门控提升。

## 6. 当前仍存在的关键问题

### 6.1 单模态主导样本会被误伤

这是目前最需要继续解决的问题。原始表征 MOSEI 中，在“文本 solo 预测已经是三个模态中最准确”的样本组里，新门控的样本级 MAE 平均反而增加约 0.0156。

说明新门控整体 MAE 的下降，可能主要来自一部分容易样本或多模态互补样本；它尚未保证：

```text
某模态在当前样本确实最可靠
        ⇒
门控在当前样本给它足够高的有效权重
```

新窗口必须增加按“最佳 solo 模态 / 模态缺失模式 / 预测分歧 / 标签强度”分组的诊断，不能只看总体均值。

### 6.2 Shapley 教师和任务最优权重不是同一个目标

Shapley 衡量的是 joint head 在子集效用上的边际贡献；最终部署却是 solo logits 的加权和。两个路径不同，因此：

- Shapley 对某模态评价高，不保证 solo head 的当前输出最适合加大权重；
- 任务损失校准可能提高 MAE，但会降低预测门控与 Shapley 的相关性；
- 只报告 Shapley 拟合误差，不能证明部署性能提升；
- 只报告部署指标，也不能证明门控学到了贡献。

后续实验至少要同时报告：Shapley 相关性/排序一致性、总体任务指标、单模态主导子组指标。

### 6.3 M3ED 负增益不能隐藏

当前 E2 表征的 M3ED 10 种子结果仍为负。可能原因包括：

- 中文对话情绪类别的上下文依赖更强，solo 预测加权不能完整表达对话交互；
- E2 音频表征已经很强，门控的微小误差会破坏稳定的已有权重；
- 当前证据特征是逐句的，未显式使用说话人、对话场景和历史冲突；
- 分类的 weighted F1 对少数类别损失不敏感，门控可能优化了总体类别而牺牲少数类别。

在没有解决这些问题前，不能把 M3ED 作为创新点二的正向主证据。

### 6.4 当前门控仍然存在“弱模态平均化”风险

bounded 权重把权重限制在窄区间内，这是稳定性优点，但也限制了真正的模态选择幅度。当前公式适合“温和重加权”，不适合极端缺失或强冲突场景。

因此后续不要简单把 `lambda` 调大来追求收益。那会同时改变创新点二的定义和公平性。应先区分：

- 权重被 bounded 限制导致的上限问题；
- 门控评分方向错误导致的选择问题；
- solo/joint 路径不一致导致的目标问题。

### 6.5 为什么之前改动成本大，以及后续如何降成本

之前的成本大，主要不是 `EvidenceRouter` 本身，而是同时改了配置、checkpoint 兼容、训练入口、多个门控变体、验证脚本和审计脚本，且每个数据集都重复做了多种 seed 实验。

后续三个创新点合并时，创新点二应采用“单入口、单默认、少量对照”的方式：

1. 只保留一个 `gate_architecture=evidence` 的生产路径；
2. `constant`、旧 `legacy`、`uniform` 只在消融脚本中保留，不进入主模型分支；
3. 不重新训练底座，只在底座完成后训练门控头；
4. 不复制三套 `model.py`，把门控作为同一个 `UGFModel` 内的可选模块；
5. 只保留一个 Shapley 计算函数和一个 bounded 部署函数；
6. 先用 3 个 seed 验证接口和梯度隔离，确认无误后再跑 10 个 seed；
7. 只有最终方案冻结后才做 test，不为每个候选门控重复打开 test。

这样创新点二的新增成本主要是一个门控头和一次门控训练，而不是重新训练整个多模态模型。

## 7. 后续三个创新点合并时，创新点二应如何接入

推荐接入顺序：

1. 先合并创新点一、三的编码/弃权逻辑，但默认关闭其新开关，验证旧模型复现；
2. 在合并后的同一前向中生成最终 `cur_embs` 和 `solo logits`；
3. 创新点二只读取这些最终表示和证据，输出 `mu`；
4. 只在一个位置调用 bounded `deploy_weights`；
5. 创新点三如果需要弃权，应读取门控后的不确定性/冲突诊断，但不能再次改写 Shapley 或 bounded 权重；
6. 创新点一如果改变 joint head，必须重新定义并验证 Shapley 子集效用，因为 Shapley 教师对应的是 joint head；
7. 重新做“关闭一、三 → 只开二 → 开二加一 → 开二加三 → 三者全开”的消融。

禁止出现以下结构：

```text
创新点一先改权重
创新点二再次改权重
创新点三又对输出做一次隐式重加权
```

否则无法判断收益来自哪个创新点，也会破坏“Shapley + 中心化 + bounded 权重”三件套的可解释性。

## 8. 新窗口实施清单

新窗口开始修改前，按以下顺序执行：

1. 阅读本文和 `代码/创新点2_门控对照/说明.md`；
2. 对比 `代码/00_原始代码/code/n6/` 与 `代码/创新点2_门控对照/code/n6/`；
3. 确认 `measure_shapley` 和 `deploy_weights` 的原始 AST/数学逻辑不变；
4. 只保留一个最终默认门控名称，建议为 `evidence_task`，其余作为 ablation；
5. 明确创新点一、三是否改变 joint head、solo head、表示或 mask；
6. 重新计算 Shapley 教师，不复用改变 joint head 后的旧教师缓存；
7. 先做 3 seeds smoke test，再做预注册的 10 seeds；
8. 只在最后一次、方案冻结后申请正式 test 评测；
9. 最终报告必须同时包含总体指标、模态主导子组、缺失模态、类别/情绪分组和 Shapley 对齐指标。

## 9. 最终推荐配置

在创新点一、三尚未确定前，创新点二暂时冻结为“候选设计”，不要把它硬编码成最终总模型：

```text
gate_architecture = evidence
gate_objective = task + 0.3 * shapley_mse + 0.1 * rank_loss
gate_input_detach = true
detach_utility_path = true
utility = shapley
use_bounded_w = true
bounded_lambda = 0.3
contrib_correct = false
```

这套配置是当前最有证据支持的统一候选，不是已经证明在所有数据集上最优的定理。创新点一、三合并后必须重新验证，尤其要重新检查 M3ED 和单模态主导样本。
