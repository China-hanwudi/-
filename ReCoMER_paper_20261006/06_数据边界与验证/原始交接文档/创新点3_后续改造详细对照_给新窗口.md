## 1. 先给结论

创新点三最初的核心必须保留：

    当前句
      ↓
    历史句子候选集合 + 空候选
      ↓
    自动打分 / softmax 竞争
      ↓
    保留历史，或选择空候选而放弃历史

它不是普通的固定历史权重，也不是一个与历史候选无关的独立 sentence gate。创新点三的卖点是：模型在历史证据进入后续模块之前，自动判断“这次是否应该听历史”。

当前需要保留的核心不变：

1. 不修改历史句子本身，也不把历史句子预先删掉。
2. 历史候选和空候选仍然参加同一次自动竞争。
3. 空候选被选中后必须是真正的弃权，而不是只把一个概率报出来。
4. 弃权必须同时切断历史汇聚残差和原始历史 token 路径。
5. 训练时可以使用历史效用监督，但推理时不能使用标签或测试集信息。

因此，后续工作的重点不是推翻创新点三，而是修正“空候选容易变成软拒绝、历史仍从旁路进入”的实现问题，并把弃权行为和实验指标记录清楚。

## 2. 原始创新点三是什么

### 2.1 原始结构

原始结构可以写成如下形式：

    当前句表示 q
          │
          ├── 历史句候选 h1, h2, ..., hK
          └── 空候选 h∅
                   │
                   └── 对 K+1 个候选打分
                             │
                             └── softmax
                                   │
                  ┌────────────────┴───────────────┐
                  │                                │
            历史候选权重                     空候选权重
                  │                                │
            汇聚历史证据                     表示弃权倾向
                  │                                │
                  └──────────进入反馈/联合模块───────┘

可用公式表示为：

\[
s_{m,k}=\frac{q_m^\top h_{m,k}}{\sqrt d},\qquad
[a_{m,1},\ldots,a_{m,K},a_{m,\varnothing}]
=\operatorname{softmax}(s_{m,1},\ldots,s_{m,K},s_{m,\varnothing}).
\]

历史汇聚结果为：

\[
p_m=\sum_{k=1}^{K}a_{m,k}h_{m,k}.
\]

空候选的概率 a_{m,∅} 代表模型的弃权倾向，通常也可以写成保留概率：

\[
r_m=1-a_{m,\varnothing}.
\]

### 2.2 原始机制的研究意义

历史信息不是永远有利：

- 当前句与历史连续时，历史通常可以帮助判断情绪延续；
- 当前句发生情绪翻转时，历史可能把模型带向错误类别；
- 没有有效历史时，模型不应被迫使用一个无意义的历史表示。

所以创新点三不是“让模型尽可能多用历史”，而是让模型自动决定什么时候保留历史、什么时候放弃历史。

### 2.3 原始实现暴露出的关键问题

早期代码/实验中出现过以下问题。下一个窗口必须逐项检查，不得把旧问题带回去：

1. 空候选开关没有完全生效。某些旧路径即使配置关闭了空候选，也仍可能把 null_emb 拼入候选集。
2. softmax 空概率只是相对竞争概率。a_empty 高，不等于后续模块完全没有历史信息。
3. 历史效用监督太弱。单纯使用 label_match 只能说明历史标签是否相同，不能严格表示“历史使当前损失变好还是变坏”。
4. 残差旁路没有被完整切断。旧实现可能遮掉了联合 token，但仍把历史池化结果通过反馈残差加回当前表示。
5. 统计口径不一致。旧的 abstain_rate 有时记录的是空候选平均概率，不是实际二值弃权率。
6. 空候选选出后仍可能进入后续历史模块。这会把“弃权”变成软降权，而不是完整弃权。

这些问题不意味着核心想法错误，而是说明“空候选竞争”和“后续路径切断”必须作为一个整体实现。

## 3. 本次修改保留什么、修改什么

### 3.1 必须保留的核心卖点

以下内容属于创新点三的核心，不能为了追求某个数据集的分数而删掉：

- 历史候选集合仍然显式存在；
- 空候选仍然显式存在；
- 候选之间仍然自动竞争；
- 弃权决策发生在历史证据进入后续模块之前；
- 弃权后历史路径被切断；
- 训练和推理都能输出可解释的保留/弃权诊断量。

### 3.2 可以修改的部位

可以在不改变上述核心的前提下修改：

- 空候选 logit 的校准方式；
- softmax 的温度或归一化方式；
- 由当前句、历史质量、当前/历史差异构成的门控特征；
- 历史效用监督；
- 训练时软门控与推理时硬门控的衔接方式；
- 诊断指标和消融实验。

不能把这些“可修改部位”改成一个完全独立、完全绕开候选竞争的句级二分类器，除非另立一个明确的附加消融分支，并且不再把它称为核心模型。

## 4. 当前推荐的新结构

### 4.1 结构总览

当前推荐保留“历史候选 + 空候选”的结构，同时增加一个由历史效用特征产生的空候选校准项：

    当前句 q_m
          │
          ├── 当前句特征、历史质量特征、当前-历史差异特征
          │                         │
          │                         └── utility calibrator
          │                                      │
          │                                      └── null-bias
          │
          ├── 历史候选 h_m,1 ... h_m,K ── 原始候选分数
          └── 空候选 h_m,∅ ───────────── 原始空候选分数 + null-bias
                                          │
                                          └── softmax 或 sparsemax
                                                 │
                                  ┌──────────────┴──────────────┐
                                  │                             │
                           历史保留概率 r_m                空候选概率
                                  │                             │
                                  └── gate / hard decision ────┘
                                                 │
                            保留：历史残差和历史 token 都可进入
                            弃权：历史残差=0，历史 token mask=0

### 4.2 候选分数

对于每个模态 m 和历史槽位 k：

\[
s_{m,k}=\frac{q_m^\top h_{m,k}}{\sqrt d}.
\]

空候选分数为：

\[
s_{m,\varnothing}
=\frac{q_m^\top h_{m,\varnothing}}{\sqrt d}
+\beta\log\frac{1-r_m}{r_m}.
\]

其中：

- r_m 是 utility calibrator 预测的历史保留概率；
- β 是空候选校准强度；
- r_m 必须经过数值裁剪，例如 r_m ← clamp(r_m, ε, 1-ε)；
- 该项只调整空候选相对于历史候选的竞争位置，不删除历史候选。

归一化可以使用：

\[
\mathbf a_m=\operatorname{softmax}(\mathbf s_m/\tau),
\]

或者作为稀疏化消融使用 sparsemax。主模型优先使用 softmax，sparsemax 只作为对照，不要直接把 sparsemax 当作已证明更好的最终方案。

### 4.3 保留与弃权的实际执行

历史汇聚结果：

\[
p_m=\sum_{k=1}^{K}a_{m,k}h_{m,k}.
\]

历史反馈残差：

\[
e'_m=e_m+g_m\,\gamma_m\,p_m.
\]

其中 g_m 是最终执行门：

- 训练阶段可以使用连续门或 straight-through hard gate；
- 推理和正式评估阶段必须支持硬弃权；
- 当空候选被判定为弃权时，g_m=0；
- g_m=0 时，不能只将 p_m 置零，还必须清除原始历史 token 路径。

### 4.4 真正的硬弃权

空候选被选中后的逻辑必须等价于：

    空候选胜出
        ↓
    历史反馈残差 = 0
    历史 token mask = 0
    joint history mask = 0
    masked mean 不包含历史槽位
    历史聚合结果 = 0 或不进入后续模块

禁止以下“伪弃权”实现：

    空候选概率升高
        ↓
    只把历史权重乘一个较小系数
        ↓
    原始历史 token 仍进入 joint head

这只能叫软降权，不能叫创新点三的硬弃权。

## 5. Utility calibrator 的特征定义

当前推荐的特征维度为 24，特征只用于训练/推理时的模型输入，不包含标签。正式实现需要检查维度、顺序和缺失值处理是否完全一致。

| 索引 | 特征组 | 含义 |
|---:|---|---|
| 0–2 | 当前 solo 熵 | T/A/V 三个当前模态的预测不确定性 |
| 3–5 | 当前 top margin | T/A/V 当前最高类别与次高类别的差距 |
| 6–8 | 当前模态存在性 | T/A/V 当前输入是否有效 |
| 9–11 | 历史有效槽位比 | 每个模态可用历史槽位比例 |
| 12–14 | 当前-历史 JS 差异 | 当前预测分布与历史摘要分布的差异 |
| 15–17 | 历史摘要熵 | 各模态历史摘要的不确定性 |
| 18 | 同说话人比例 | 历史候选中同说话人比例 |
| 19 | 说话人元数据可用性 | 是否存在可靠的说话人信息 |
| 20 | 总历史有效比例 | 所有模态的历史有效程度 |
| 21 | 文本历史平均余弦 | 当前文本与历史文本的平均相似度 |
| 22 | 文本历史最大余弦 | 当前文本与历史文本的最大相似度 |
| 23 | 注意力加权文本余弦 | 按历史注意力加权的文本相似度 |

实现要求：

1. 缺失模态不能产生 NaN；用明确的零值和存在性特征区分“缺失”和“确实为零”。
2. 特征归一化统计只能来自训练拟合集，不能读取验证集标签或测试集。
3. E5 使用 base 特征，E6 使用全部 24 个特征，保持网络参数规模可比。
4. 训练和推理的特征顺序必须完全一致；保存 checkpoint 时记录特征版本。
5. 新增特征不能偷偷改变历史候选集合本身，否则无法判断收益来自门控还是候选构造。

### 6.1 E5 主候选

E5 的含义：

    原始历史候选 + 空候选
            ↓
    24 维 utility calibrator 的 base 输入
            ↓
    校准空候选 logit
            ↓
    softmax 自动竞争
            ↓
    硬弃权时切断 residual + raw history token path

### 6.2 E6 语义特征候选

E6 在 E5 基础上保留文本历史相似度等语义特征。E6 的作用主要是检验“更丰富的语义特征是否比基础特征稳定”。如果 E6 与 E5 结果几乎完全相同，不得写成“语义特征带来额外提升”，应如实报告为未观察到独立增益。

### 6.3 E7 sparsemax 候选

E7 用 sparsemax 替换 softmax，观察是否会产生更明确的零权重和更清晰的空候选决策。它是归一化方式消融，不应与 E5 同时改变特征、损失、数据划分和阈值。

### 6.4 sentence 旧分支

旧 sentence 分支可以保留用于回归和历史对照，但不要将其与新 utility 空候选分支混称。除非新窗口另有严格实验，否则：

- 不把旧 sentence 分支的结果当作新核心结果；
- 不同时打开旧 sentence gate 和 E5/E6/E7；
- 不在没有单独消融的情况下，把两套 gate 叠加后称为“创新点三”。

## 7. 已修复的关键 bug：必须防止回归

### 7.1 旧 bug 的表现

旧 utility 分支曾经出现过：

    空候选被选中
        ↓
    raw history token path 被 mask
        ↓
    但 history pooled residual 仍然加到当前 embedding

结果是：指标看起来像进行了弃权，实际上历史信息仍通过 residual bypass 进入模型。这会使“硬弃权”结论失真。

### 7.2 当前修复要求

当前实现已把以下路径统一纳入 history_gate_applied/最终执行门控制：

1. 历史反馈残差；
2. joint history token mask；
3. history masked mean；
4. 其他直接使用历史池化结果的旁路。

必须保留单元测试：

    test_utility_empty_decision_disconnects_residual

新窗口修改 model.py 后，必须重新运行该测试。若测试失败，停止后续正式实验，先修复路径断开问题。

### 7.3 必须保留的诊断接口

至少保留：

- history_override=None：正常模型决策；
- history_override=0：强制弃权；
- history_override=1：强制保留历史。

三个设置应只改变历史路径，不应意外改变当前句编码器、标签或数据划分。该接口用于做路径正确性测试和上限/下限分析，不用于替代正式模型结果。

## 8. 历史效用监督：当前状态与正确用法

### 8.1 为什么需要 utility

label_match 只能表示历史标签和当前标签是否相同，但不等于历史一定有用。例如：

- 标签相同但历史文本很模糊，历史可能仍然有害；
- 标签不同但当前上下文需要历史才能识别翻转，历史也可能有用；
- 模态缺失时，历史的作用可能和标签匹配没有直接关系。

更合理的效用定义是：

\[
u=\mathcal L_{\text{history-off}}-\mathcal L_{\text{history-on}}.
\]

- u > 0：历史降低损失，倾向保留；
- u < 0：历史增加损失，倾向弃权；
- u ≈ 0：不强行监督。

### 8.2 teacher cache 的规范

如果启用 utility cache，必须遵循：

1. teacher 只在训练拟合集上构建；
2. 先得到 history-off 和 history-on 的损失，再计算 u；
3. 将 utility 映射成保留目标，例如 target_keep=sigmoid(u/loss_scale)；
4. 验证集只能用于模型选择，不能反向生成训练 utility；
5. 测试集在结构冻结前完全不读；
6. cache 记录数据集、划分、teacher checkpoint、特征版本和构建时间。

### 8.3 当前实验的证据边界

当前多数据集正式矩阵主要是端到端任务损失训练的 E5/E6/E7，不应误写成“所有正式结果都使用 teacher utility cache”。MELD 已有 cache 构建和 smoke 验证，但要对所有数据集作 utility-supervised 结论，必须分别构建各自的 train-only cache 并按同一协议重跑。

## 10. 必须补做的实验

### 10.1 最小主实验矩阵

所有数据集、所有分支使用完全相同的数据划分、训练预算、早停规则和随机种子：

| 编号 | 配置 | 目的 |
|---|---|---|
| B0 | 无历史 | 测量历史机制的总体必要性 |
| B1 | 原始空候选 | 对照原始创新点三 |
| E5 | utility + softmax + base features | 主候选 |
| E6 | utility + softmax + semantic features | 特征消融 |
| E7 | utility + sparsemax | 归一化消融 |
| U0 | E5 无 utility cache | 判断端到端任务损失本身的效果 |
| U1 | E5 + train-only utility cache | 判断 utility 监督是否带来独立收益 |

如果算力有限，先完成 B0/B1/E5/E6/E7，再对 E5 做 U0/U1。不要只跑提升最明显的数据集。

### 10.2 每次实验必须报告

除主任务指标外，至少记录：

- overall MAE/F1/Weighted-F1；
- empty_prob_mean；
- empty_any_rate；
- 实际二值 hard_abstain_rate；
- keep_prob_mean；
- 历史残差范数（保留组/弃权组）；
- 历史 token 实际 mask 比例；
- 有历史/无历史子集；
- 历史同标签/异标签子集；
- 情绪延续/情绪翻转子集（若数据集支持）；
- 不同历史槽位数量分组；
- 3 个 seed 的均值、标准差和逐 seed 结果。

必须区分：

    empty_prob_mean       = 空候选软概率平均值
    hard_abstain_rate     = 最终二值决策中的实际弃权比例
    keep_prob_mean        = 历史保留概率平均值

三者不能互相替代。

### 10.3 失败分析顺序

如果某个数据集下降，按以下顺序排查：

1. 强制 history_override=0/1，检查是否是历史路径本身导致下降；
2. 检查 hard gate 是否真的切断 residual 和 token path；
3. 检查 hard_abstain_rate 是否极低或极高；
4. 检查历史槽位、同标签比例、说话人信息和缺失模态；
5. 比较 B1/E5 的逐样本决策差异；
6. 检查 utility 特征是否出现 NaN、常数化或数据泄漏；
7. 最后才调整 β、阈值或温度，且每次只改一个因素。

## 15. 最终交接口径

下一个窗口完成后，至少要能回答以下问题：

1. 空候选是否仍然和真实历史候选自动竞争？
2. 空候选获胜时，历史 residual 和 raw history token 是否都被切断？
3. hard_abstain_rate 与 empty_prob_mean 是否分开记录？
4. utility cache 是否只使用 train/fit 数据构建？
5. E5、E6、E7 是否只改变各自声明的单一因素？
6. M3ED 下降的原因是否已有证据，而不是凭猜测调参？
7. 当前结论是否明确区分“有效信号”“持平”“下降”和“尚未验证”？
8. 在结构冻结前是否完全没有使用 test？

本创新点三最终要证明的不是“每个数据集都提升”，而是：

    模型能够在历史有益时自动保留历史，
    在历史有害或无效时自动选择空候选，
    并且选择弃权后真的切断历史信息路径。

只有在上述机制正确、诊断量可信、跨数据集结果和失败案例都被如实报告后，才可以把创新点三写成完整的方法贡献。
