# 创新点三实验数据整理报告

日期：2026-10-04

## 1. 报告范围

本报告整理创新点三“历史候选 + 空候选 + 自动弃权”机制目前已经完成的有效实验数据。

报告遵循以下边界：

- 只整理已完成且通过修复后路径检查的结果。
- 不把 residual bypass 修复前的旧结果混入有效结果。
- 当前结果全部来自 train/fit/inner-dev 或 valid 侧；结构冻结前没有读取 test。
- 结果用于机制筛选和问题定位，尚不能直接写成“所有数据集稳定提升”。
- E5、E6、E7 仍属于候选模型，尚未完成最终 test 评估和全数据集 utility-cache 正式矩阵。

---

## 2. 模型和实验定义

| 名称 | 定义 | 作用 |
|---|---|---|
| B0 | 无历史参考 | 判断历史信息总体是否有用 |
| B1 | 原始空候选机制 | 创新点三原始对照 |
| E5 | utility 空候选校准 + softmax + base 特征 | 当前主候选 |
| E6 | utility 空候选校准 + softmax + semantic 特征 | 特征消融 |
| E7 | utility 空候选校准 + sparsemax | 归一化消融 |

四个历史机制都保留真实历史候选和空候选的自动竞争。

E5/E6 的主要差异是空候选 logit 校准所使用的特征；E7 只替换归一化方式。正式比较时不应同时改变数据划分、训练预算、阈值和损失。

### 3.3 当前能支持的结论

当前数据支持：

1. 创新点三在 IEMOCAP 和 MOSEI 上表现出正向信号。
2. MELD 上基本持平，E5 没有形成稳定的大幅提升。
3. M3ED 上当前变差，不能回避，必须单独做 gate 分布和失败样本分析。
4. E5 是目前最值得继续验证的候选，但还不能称为跨数据集最优。
5. E6 与 E5 在当前矩阵中几乎相同，暂时不能声称 semantic 特征带来独立收益。
6. E7 当前没有显示出相对于 E5 的稳定优势。

当前不能支持：

- “创新点三在所有数据集都提升”；
- “E5 已经是最终模型”；
- “sparsemax 一定优于 softmax”；
- “当前结果已经可以替代最终 test 评估”；
- “utility cache 已经用于所有正式多数据集结果”。

## 4. 数据集历史质量

以下统计来自 valid 侧历史诊断，不使用 test：

| 数据集 | 有历史比例 | 平均历史槽位数 | 有同标签历史比例 | 槽位匹配比例 |
|---|---:|---:|---:|---:|
| MELD | 0.8972 | 2.3968 | 0.6121 | 0.3676 |
| M3ED | 0.9447 | 2.5168 | 0.7538 | 0.5845 |
| IEMOCAP | 0.8888 | 1.8401 | 0.8485 | 0.7743 |
| MOSEI | 0.4842 | 1.1737 | 0.2759 | 0.1362 |

解释：

- IEMOCAP 的历史匹配质量最高，E5/E6 的提升与“历史较可靠”相符。
- MOSEI 的历史质量最低，但 E5/E6 的 MAE 反而改善，说明自动拒绝低质量历史可能有效。
- M3ED 的历史质量看起来较好，但当前结果仍下降，说明“历史多/历史同标签”并不等于“当前 gate 行为正确”。
- MELD 的历史质量中等，模型整体没有明显增益，说明空候选校准仍可能需要更准确的 utility 监督。

## 5. 弃权与保留诊断

E5 seed=7 的部分 valid 诊断如下：

| 数据集 | empty_mean | empty_any_rate | keep_prob | hard_keep |
|---|---:|---:|---:|---:|
| M3ED | 0.0576 | 0.0610 | 0.9982 | 0.9447 |
| IEMOCAP | 0.1318 | 0.1112 | 0.9636 | 0.8888 |
| MOSEI | 0.5275 | 0.5265 | 0.9638 | 0.4842 |

指标含义必须严格区分：

- empty_mean：空候选软概率的平均值；
- empty_any_rate：样本中出现空候选倾向的比例；
- keep_prob：模型输出的连续历史保留概率；
- hard_keep：最终硬决策下的历史保留比例；
- hard_abstain_rate：1 − hard_keep，是实际二值弃权比例。

不能把 empty_mean 直接称为弃权率。

初步解释：

- M3ED 的 hard_keep 很高，模型几乎保留所有历史。若少数错误历史影响较大，可能导致当前性能下降。
- IEMOCAP 的历史大多数被保留，同时整体指标提升，说明保留的历史大部分可能确实有帮助。
- MOSEI 的 hard_keep 较低，模型拒绝了相当一部分历史，这与 MOSEI 较低的历史质量一致。

## 8. 下一步实验整理建议

### 8.1 优先级一：先解释 M3ED 下降

建议固定 E5，不先改公式，按顺序输出：

1. B1 与 E5 的逐样本保留/弃权差异；
2. hard_keep 和 hard_abstain_rate 的分布；
3. 历史槽位数量分组指标；
4. 同标签历史和异标签历史分组指标；
5. 强制 history_override=0 和 history_override=1 的结果；
6. 保留组与弃权组的历史残差范数；
7. 失败样本的当前预测、历史候选、空候选分数。

### 8.2 优先级二：完成 utility cache 对照

对每个数据集分别生成 train-only cache：

- teacher 只读取 train/fit；
- utility = history-off loss − history-on loss；
- cache 不读取 valid 标签以外的额外信息；
- U0 和 U1 使用完全相同的网络和训练预算；
- 单独报告 U0/U1，不能覆盖 E5 的无 cache 结果。

### 8.3 优先级三：扩大 seed

在代码和协议冻结后：

- 先固定 seed=7、13、17 作为已有复核；
- 再增加到 10 seed；
- 报告逐 seed 结果、均值、总体标准差和置信区间；
- 不以单个最佳 seed 作为主结论。

### 8.4 优先级四：最后才做 test

只有满足以下条件，才进行 test：

- residual 和 token 两条历史路径测试通过；
- B0/B1/E5/E6/E7 配置冻结；
- utility cache 是否启用已经决定；
- 训练/验证协议和 checkpoint 已冻结；
- 所有正式日志无异常；
- test 只运行一次最终评估，不用于调阈值或选模型。

## 10. 一句话结论

目前最稳妥的结论是：

创新点三的核心机制已经实现并通过了历史路径硬断路修复验证；在 IEMOCAP 和 MOSEI 上出现正向信号，在 MELD 上基本持平，在 M3ED 上暂时下降。因此当前应把 E5 作为继续验证的主候选，同时优先解释 M3ED 失败、完成 train-only utility-cache 对照和更稳定的多 seed 验证，暂时不能宣称该机制在所有数据集上普遍提升。
