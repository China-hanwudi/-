# 双数据集历史负迁移 Benchmark 探索报告

日期：2026-08-07

协议：`negative_transfer_benchmark_v1`
结论属性：**探索性，不是确认性结果**

## 1. 本报告回答什么

本报告统一审计 EmotionTalk validation 与 MELD dev 中“加入同一说话人的历史后，相对 current-only 的预测损失是否上升”。它回答三个问题：

1. 历史负迁移是否真实出现，而不是只看平均准确率；
2. 风险是否重尾并集中在少数对话；
3. 预测“会不会受伤”和预测“会伤多严重”是否是同一个任务。

定义：

\[
r_t=L(y_t,\hat y_t^{history})-L(y_t,\hat y_t^{current})
\]

`r_t > 0` 表示使用历史造成伤害，`r_t < 0` 表示历史有益。该量是相对于冻结预测模型的决策效用，不是历史的真实心理因果效应。

## 2. 数据与统计单位

| 数据集 | 有历史查询 | bootstrap 聚类单位 | 伤害率 | 平均 excess loss（95% cluster CI） | p90 | CVaR90 |
|---|---:|---:|---:|---:|---:|---:|
| EmotionTalk validation | 1,770 | 71 个 `group/dialogue` | 33.90% | 0.0564（-0.0213, 0.1400） | 1.098 | 2.101 |
| MELD dev | 765 | 103 个 dialogue | 43.27% | 0.0842（-0.0594, 0.2225） | 1.623 | 3.162 |

所有区间按完整对话做 2,000 次 cluster bootstrap，未把 utterance 当作独立样本。EmotionTalk 的 dialogue 编号跨 group 重复，因此实现使用 `group/dialogue` 复合键；错误合并 cluster 的首轮结果已作废并隔离。

## 3. 主要探索发现

### 3.1 仅看平均值会掩盖风险

两个数据集的平均 excess loss 的 95% CI 都跨 0，但单条查询伤害率分别达到 33.90% 和 43.27%，且 p90/CVaR90 明显为正。最差 10% 对话贡献了 EmotionTalk 约 33.97%、MELD 约 41.49% 的正 regret。历史效果是混合且重尾的，不能只报告“平均加历史是否更准”。

### 3.2 符号与严重度发生错配

现有 selector 有两种排序方式：

- `harm-probability`：优先选预测为“不容易受伤”的查询；
- `mean-risk`：优先选预测 excess loss 均值更低的查询。

两者并不等价。MELD 文本在约 10% 覆盖时，harm-probability 的平均策略 regret 为 **+0.0415**，95% CI **[0.0143, 0.0709]**；mean-risk 则为 **-0.0700**，95% CI **[-0.0981, -0.0361]**。然而 mean-risk 被选样本仍有约 51.3% 的伤害事件，说明少数大收益可以掩盖较多小伤害。

EmotionTalk 三模态 mean-risk 在 10%、25%、50% 覆盖下的平均策略 regret 均为负且 cluster CI 上界小于 0；同一 selector 的 harm-probability 在 25% 与 50% 覆盖下反而为正。该模式支持进一步检验“伤害符号”和“伤害严重度”需要联合建模。

### 3.3 严格 q90 gate 仍失败

旧 CARMA 的严格 q90 上界规则几乎拒绝全部历史，且极低覆盖下仍未形成可靠安全保证。因此不能把“mean-risk 排序看起来有效”写成安全方法已经成功；尾部校准仍是核心未解决问题。

## 4. 可证伪假设与下一步

- H1：负迁移是混合/重尾结果；只优化 `P(r_t>0)` 会忽略严重度。
- H2：只优化条件均值可降低平均 regret，但不能保证伤害率或 q90/CVaR。
- H3：逐候选、逐集合的 sign × severity/quantile 分布模型，加上 coverage-constrained risk control，才能同时控制平均、发生率和尾部风险。

下一步严格使用 train-only 的确定性角色切分：

| 角色 | SHA-256 桶 | 允许用途 |
|---|---:|---|
| base 与 utility 拟合 | 0–64 | 训练 cross-fit base、构造 OOF utility、拟合 utility heads |
| 模型选择 | 65–79 | 反证符号—严重度错配、选择预注册候选 |
| 校准 | 80–89 | q90/RCPS 阈值与覆盖校准 |
| 内部 holdout | 90–99 | 在方法与阈值冻结前不得读取性能 |

只有 H1–H2 在 65–79 模型选择组复现，才进入 SCU-Set 的随机历史子集增强；否则停止复杂模型，转向 benchmark/否定性论文路线。
