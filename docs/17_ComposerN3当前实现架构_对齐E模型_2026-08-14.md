# ComposerN3 当前实现架构（对齐本地可训练 `模型` 包）

> 冻结日：2026-08-14  
> 依据：可运行代码 `模型/n3_affect/`（与本地训练用模型包同构），**不是**文件清单对照，而是**网络与数据流架构**。  
> 与 `docs/14` / `docs/15` 中尚未落地的「Qwen 原生三模态 Phase A/B」目标方案区分：那些是后续升级合同；**当前仓库可训练主架构如下。**

---

## 1. 一句话

**冻住 Qwen3-Omni thinker 只做文本表征（可离线缓存为 2048-d）+ 音视频侧车特征 → 六路投影到 `d_model=128` → 共享 3×3 关系 → 多效应双向效用混合 → 两级门控 → Transformer 上下文 → 7 类情感分类（辅以 VAD）。**

---

## 2. 数据流（实现态）

```text
原始 MELD 话语 (text + mp4)
        │
        ▼
[离线] extract_meld_features.py
  · Text e_T : 冻结 Qwen3-Omni thinker，last-token 池化 → 2048-d
  · Audio e_A : ffmpeg→wav + librosa MFCC/mel 统计 → 1536-d
  · Video e_V : ffmpeg 抽帧统计 → 768-d
  · 历史：严格过去最多 K=3 槽，写 history_mask / modality_mask
        │
        ▼
*.pt 六路特征 T_t,A_t,V_t,T_h,A_h,V_h
        │
        ▼
[训练] N3EmotionModel（仅训投影与 N3 头；不反传千问）
  ModalityProjector(e→z∈R^128)
  → current_fuse / SharedThreeByThree
  → BidirectionalUtilityHeads（19 路 effect + 可学习 mix）
  → TwoLevelGate（模态门 + 联合风险门 + 可学习历史混合）
  → TransformerEncoder 上下文
  → logits(7) + vad(3)
```

在线路径（冒烟/可选）：`SixWayEncoders` 内可挂 `OptionalHFTextTower` 冻千问；音视频仍走张量投影。正式 MELD 主路径是**离线特征 + `train_meld.py`**。

---

## 3. 模块职责（与代码类一一对应）

| 模块 | 类 / 文件 | 架构职责 |
|---|---|---|
| 配置 | `N3TrainConfig` / `configs/n3_train_v1.json` | `text_dim=2048`, `audio_dim=1536`, `video_dim=768`, `d_model=128`, 7 类标签序 |
| 六路编码 | `SixWayEncoders` | 独立投影当前/历史；应用 `history_mask`、`modality_mask` |
| 文本塔 | `OptionalHFTextTower` / `QwenTextExtractor` | 仅文本；Omni `disable_talker`；bf16 + `device_map=auto` |
| 关系 | `SharedThreeByThree` | 当前×历史 9 对低秩双线性 + type embedding |
| 效用 | `BidirectionalUtilityHeads` + `all_effect_deltas` | 当前 Möbius、历史单向双向、时序交互；softmax mix + peak hinge |
| 门控 | `TwoLevelGate` | 每模态 keep 概率 → 联合风险 → `current + scaled_history` |
| 分类 | `N3EmotionModel` | 四 token 上下文编码 → CE；`TheoryAuxHead` 做 VAD 辅助 |
| 数据 | `MELDFeatureDataset` | 读官方 split manifest + `.pt` |
| 训练 | `train_meld.py` | **只用官方 train**；train 内 10% monitor 早停；不用官方 val/test 调参 |

---

## 4. 六路与掩码约定

- 当前：`T_t, A_t, V_t`，各 `[B, D_in]` 再投影到 `[B, 128]`  
- 历史：`T_h, A_h, V_h`，特征侧为 `[K=3, D_in]`；进入关系前按 `history_mask` 池化到 `[B, 128]`  
- `history_mask`：槽位是否有真实过去轮次  
- `modality_mask`：当前 T/A/V 是否可用  
- `history_modality_mask`：池化后历史模态是否可用  
- **禁止**把未来话语写入历史槽

---

## 5. 与「目标 Phase A/B」的边界（避免架构混淆）

| 当前实现架构（本文件） | docs/14–16 目标方案（尚未作为默认实现） |
|---|---|
| Qwen **仅文本** thinker | Qwen **原生** T/A/V 三路 `e` |
| A/V = librosa / 帧统计侧车 | A/V = Omni 分模态 hidden + provenance |
| 单模型 ComposerN3 端到端（效用+门控开） | Phase A emotion-only A0/A1，再 Phase B 接 `phi_k` |
| 7 类 MELD 标签 | 合同中另有四分类等变体 |
| `train_meld` + monitor 早停 | `STOP_BEFORE_TEST_A` / 独立 write-once test |

升级到目标方案时，应**替换特征生产与训练合同**，而不是否认本架构曾作为可训练主线存在。

## 6. 入口命令（架构落地方式）

```bash
# 1) manifest（官方 train/dev/test）
python -m n3_affect.generate_meld_manifests --out-dir <manifests>

# 2) 离线特征（冻千问文本 + 侧车 A/V）
python -m n3_affect.extract_meld_features \
  --manifests train.csv val.csv test.csv \
  --out-dirs feat/train feat/val feat/test

# 3) 训练 N3（仅 train split）
python -m n3_affect.train_meld \
  --train-manifest train.csv --train-features feat/train \
  --out-dir <train_out>

# 4) 评估（val/test 须遵守授权与禁泄漏规则）
python -m n3_affect.eval_meld --checkpoint best.pt --manifest ... --features ...
```

服务器也可使用 `模型/run_meld_v3.sh`（内含默认绝对路径，按机器修改）。
