# 最新执行基线与 GitHub 旧方案差异（2026-08-13）

> 状态：当前最高优先级执行说明（ACTIVE OVERRIDE）
>
> 适用范围：Phase A 的 Qwen 三模态管线与 emotion-only 基线、Phase B 的完整 N3 机制实验，以及 MELD、IEMOCAP、EmotionTalk 三数据集的分别训练与统一对照
>
> 结论边界：本文规定“现在做什么、怎么做、做到什么算通过”。旧文档继续保留用于追溯，但冲突之处以本文为准。本文不代表 N3 已取得正式性能结论。

## 1. 一句话目标

不是用一个数据集训练后直接宣称能迁移到另外两个数据集，而是用**同一套冻结的 CARMA-Affect/N3 方法和统一评估合同，在 MELD、IEMOCAP、EmotionTalk 上分别训练、验证和测试**，检查该框架能否跨数据集稳定有效。默认产出是每个数据集各自的模型/checkpoint 和结果；跨数据集零样本迁移属于额外实验，不替代三数据集内验证。

## 2. Phase A — Qwen 三模态管线与 emotion-only 基线

Phase A 的目的只是在不混入完整 N3 辅助机制的情况下，先证明数据、三模态特征、严格历史、缺失回退和基础分类训练管线正确。**Phase A 通过不等于完整 N3 创新有效**，也不能替代 Phase B 的机制比较、消融与统计确认。

### 2.1 Qwen3-Omni 负责三种模态

- 主干固定为 `Qwen3-Omni-30B-A3B-Instruct`，在第一阶段**冻结权重、离线抽取特征**；
- 文本、音频、视频都由 Qwen3-Omni 处理，不再把“Qwen 只处理文本 + librosa 音频统计 + torchvision 视频统计”作为当前主线；
- 当前话语分别得到 `T_t / A_t / V_t`，严格过去历史分别得到 `T_h / A_h / V_h`；
- 三种模态必须分别保存表示、mask 和来源信息，不能只保存一个不可拆分的混合向量；
- 缓存 Qwen 输出的原始隐藏维度。N3 内部可训练的 `ModalityProjector` 再统一投影至 `d_model=128`；
- 原文档中的 RoBERTa/DeBERTa、emotion2vec/SER-WavLM、AffectNet/FER+/AU 专用编码器保留为后续 baseline/消融，不再是 2026-08-13 的当前主线。

### 2.2 样本与历史合同

- 历史窗口固定 `K=3`，只允许严格过去的话语，禁止未来信息；
- 模型接口至少包含：
  - `current_modalities`: 当前 `T/A/V` 表示；
  - `history_modalities`: 过去最多 3 条话语的 `T/A/V` 表示；
  - `current_modality_mask`，形状 `[B,3]`；
  - `history_mask`，形状 `[B,K]`；
  - `history_modality_mask`，形状 `[B,K,3]`；
- 首条话语或没有合法历史时，必须**逐样本精确回退 current-only**，不能构造伪历史，也不能用另一个 history checkpoint 的空输入近似；
- 缺失模态由 mask 表达。全零向量只能作为受审计的缺失回退，不能静默当作成功提取的真实特征。

### 2.3 第一轮训练合同

第一轮目标是验证数据和三模态管线正确，不一次性启用所有 N3 辅助任务：

```text
loss = emotion_classification_loss
utility_loss_weight = 0
vad_loss_weight = 0
history_K = 3
model_selection_metric = dev Weighted-F1
test_policy = STOP_BEFORE_TEST
```

- 第一轮先做 `emotion-only`；VAD 与双向效用分支保留接口但权重为 0；
- 用 dev Weighted-F1 选择 best checkpoint，同时记录 dev Accuracy、Macro-F1、loss；
- 训练与 dev 验证通过后停在 `STOP_BEFORE_TEST`，不得自动运行正式 test；
- test 是独立、一次性、write-once 的最终确认阶段，只有在配置、源码、特征审计和 best checkpoint 全部冻结后才能单独授权。

第一轮通过后，才依次加入共享 3×3 当前—历史关系、模态级/联合级双向边际效用、两级门控、VAD/冲突等理论变量和预注册消融。这里的分阶段执行不改变最终 N3 研究目标。

### 2.4 Phase A 固定执行链

```text
单样本 T/A/V 来源与数值证明
→ 32 train / 8 dev 冒烟
→ 全量三路离线特征与 provenance 审计
→ emotion-only train + dev
→ dev Weighted-F1 选择 best
→ STOP_BEFORE_TEST
```

每种模态必须有独立缓存和 provenance，至少绑定数据集/split、样本 ID、模态、Qwen model ID/权重版本、预处理版本、输出 shape/dtype、缺失 mask 和缓存/manifest 散列。禁止只保存一个无法拆分、无法证明三种来源的混合向量。

## 3. Phase B — 完整 N3 情感历史效用实验

Phase B 只能在相应数据集的 Phase A 管线 Gate 通过后进入；它是验证情感领域理论与双向效用创新的正式方法阶段，不得把 Phase A 的 Qwen 特征基线结果写成 Phase B 结果。

### 3.1 每个历史候选分别计算 3×3

对严格过去窗口中的每个候选 `h_k, k∈{1,2,3}`，分别保留 `h_k^T/h_k^A/h_k^V`，并计算当前 `T_t/A_t/V_t` 与该候选三种模态之间的九组关系：

```text
R_k = 3×3(T_t, A_t, V_t ; h_k^T, h_k^A, h_k^V),  k = 1,2,3
```

**禁止先将 `h_1/h_2/h_3` 聚合为一个历史向量，再只计算一次 3×3。** 候选级轴和模态级轴都必须保留到效用估计与门控阶段，以支持逐候选、逐模态归因和部分保留。

### 3.2 情感理论、真实双向效用与两级门控

- 情感理论变量固定包括 VAD、情感惯性、转折、恢复、跨模态冲突、时间距离、说话人关系和模态质量；变量必须真实接入关系/效用/门控，并通过对应消融检验，不得只写在说明中；
- 对每个 `h_k` 分别估计文本、音频、视频的模态级前向加入收益与后向删除风险，再估计该候选的联合级双向效用和不可加协同/冲突残差；
- 前向背景 `S` 与后向背景 `R` 必须是预注册的不同集合状态；禁止用同一差值换符号伪造“双向”；
- 第一级门控在候选内部按 T/A/V 决定部分保留，第二级门控决定该候选历史整体是否进入；无候选通过或风险不合格时，逐样本精确回退 independent current-only；
- 完整 N3 采用至少 5 个随机种子、按 dialogue/session/speaker 分组的配对 95% CI，以及预注册的完整强基线和组件消融。只有真实情感分类指标与合取成功门通过，才能支持完整 N3 有效性主张。

### 3.3 三数据集与 test 合同

MELD、EmotionTalk、IEMOCAP 使用同一冻结框架、接口、阶段顺序与评估原则，但在各自合法切分中**分别训练、验证和评估**，默认产生三个数据集各自的 checkpoint；不合并三个数据集训练，也不默认用一套权重零样本跑三个数据集来替代数据集内验证。每个数据集的正式 test 都需要独立授权，只运行一次并写入 write-once 结果，test 后不得回流调参。对 IEMOCAP，“一次”特指在协议完全冻结后**一次性批量执行全部 5 个预注册 held-out-Session folds**并一次性发布聚合结果，不是只选择其中一折，也不得看完某折后修改方法再继续或重跑。

## 6. MELD：旧运行问题与重新训练 Gate

### 6.1 旧运行仅作诊断

旧运行曾得到：dev Accuracy `0.5469`、Macro-F1 `0.3295`、Weighted-F1 `0.5042`；test Accuracy `0.5808`、Macro-F1 `0.3322`、Weighted-F1 `0.5418`。这些数字必须标注为 `invalid_preliminary_run`，不得进入论文主结果或反向指导超参数。

判无效的原因：

- Qwen 只处理了文本；音频来自 librosa 的 MFCC/梅尔统计，视频来自 torchvision 的颜色/空间统计；
- 视频全零：train `9477/9989`、dev `1004/1108`、test `2501/2610`，总计 `12982/13707 = 94.71%`；
- 文本表示经过随机且冻结的 `2048→256 Linear`，并非可靠训练投影；
- VAD 使用全零伪 target 却设置了非零权重 `0.1`；utility 没有真实 target 却设置了非零权重 `0.2`；
- best checkpoint 按 dev loss，而不是冻结的 dev Weighted-F1；
- checkpoint 信息不完整，且训练结束后自动读取并评估了 test。

### 6.2 Phase A 重训顺序（不得跳步）

```text
G0 数据与媒体清单通过
→ G1 单个样本的 Qwen 文本/音频/视频均成功且非伪零
→ G2 32 个 train + 8 个 dev 冒烟通过
→ G3 全量离线特征抽取与审计通过
→ G4 emotion-only 正式 train + dev，按 dev Weighted-F1 保存 best
→ STOP_BEFORE_TEST
→ 独立冻结审计与人工授权
→ G5 一次性正式 test
```

各 Gate 最低要求：

- `G0`：样本 ID、dialogue、speaker、turn、label、文本、音频、视频一一对齐；train/dev/test 不交叉；
- `G1`：分别输出 T/A/V 的 shape、dtype、finite 比例、范数、mask、媒体时长及模型标识；三路均能独立证明来自 Qwen；
- `G2`：完成 forward、backward、optimizer step 和 dev inference；loss 有限；GPU 无 OOM/illegal access；保存并可重新加载 checkpoint；
- `G3`：逐 split 报告总数、成功数、缺失数、全零数、NaN/Inf 数、维度、重复/错位数。任何异常都必须给出样本 ID 清单和原因；
- `G4`：配置、随机种子、类别顺序、class weights、源码版本、Qwen 模型/权重标识、特征 manifest/hash 与 best 指标写入 checkpoint/receipt；
- `G5`：test 输出 write-once；只在独立授权后运行一次，不再据此调参。

## 7. IEMOCAP：已通过的完整性检查与下一步

已确认的聚合事实：

- 官方压缩包字节数：`17,695,884,032`；
- MD5：`521be1e5eec425ae21fdc27c763ca813`，与官方通知一致；
- `gzip -t` 通过；解压约 29 GB；归档与落盘文件数均为 `167,323`；
- Session1–Session5、dialog、句级 WAV、dialog AVI/DivX 存在；零字节文件为 0；抽检 WAV/AVI 可读；
- `._*` 资源分叉文件约 84,027 个、`.DS_Store` 19 个，生成 manifest 时忽略，不需要为了实验而删除；
- Qwen 权重检查为 15 个 safetensors、0 个 incomplete，约 66 GB。

IEMOCAP 下一步先做 preflight/manifest，不直接训练：

1. 标签固定为四分类：`angry`、`happy=(hap+exc)`、`sad`、`neutral`；目标样本数通常约 5,531，明显偏离必须 fail closed；
2. 固定 Session 五折：
   - fold1：test S1，dev S2，train S3/S4/S5；
   - fold2：test S2，dev S3，train S4/S5/S1；
   - fold3：test S3，dev S4，train S5/S1/S2；
   - fold4：test S4，dev S5，train S1/S2/S3；
   - fold5：test S5，dev S1，train S2/S3/S4；
   五折必须作为一个预注册确认批次：开发期间只能使用各折 train/dev；获得独立 test 授权后，一次性运行五个 held-out Session、写入同一 write-once 结果包并汇总，不得逐折查看结果后改模型，也不得只挑一折报告。
3. WAV 已经是句级文件；AVI 主要是完整对话视频，必须根据转写起止时间戳裁剪/采样当前句片段，不能照搬 MELD 的句级视频文件假设；
4. manifest 必须完成 ID、标签、Session、speaker、时间戳、WAV、AVI 的对齐，并构造同一对话中的严格过去 `K=3`；
5. manifest 和 Session 隔离审计通过后，再做单样本 Qwen T/A/V 证明和小样本冒烟。

## 8. EmotionTalk：到盘后的固定处理

在上传完成前不启动训练。上传完成后按以下顺序执行：

1. 记录归档文件名、字节数和可获得的官方校验和；
2. 检查归档完整性，再解压到仓库外数据目录；
3. 生成文件清单，核对预期 split、标签、对话、speaker、音频和视频；
4. 忽略系统元数据文件，检查零字节、损坏媒体、重复 ID、跨 split 重复；
5. 构造严格过去 `K=3` 和三类 mask；
6. 通过单样本 Qwen T/A/V 证明和 32/8 冒烟后，才进入全量特征抽取与训练。

- `模型/n3_affect/encoders.py` 把 Qwen3-Omni 注册为 `HF_TEXT_TOWERS`，只在 `forward_texts` 中消费文本；`A_t/A_h` 和 `V_t/V_h` 仍只是对外部 sidecar 做 `ModalityProjector`，尚不能证明音频/视频由 Qwen 提取；
- `模型/configs/n3_train_v1.json` 仍设置 `utility=0.2`、`vad=0.1`，与第一轮 emotion-only 冻结合同冲突；
- 当前 `模型/n3_affect/model.py` 的输入仍是每个样本一组聚合 `T_h/A_h/V_h`，没有完整实现 `[B,K,...]` 的 `K=3` 历史以及三类 mask；
- `模型/n3_affect/train.py` 是 synthetic smoke trainer，不是 MELD/IEMOCAP/EmotionTalk 正式数据训练器，也没有 dev Weighted-F1 best-checkpoint 与 `STOP_BEFORE_TEST` 流程。
- 完整 Phase B 还未证明已实现：现有代码没有形成“对每个 `h_k` 分别计算 3×3、候选级模态/联合真实双向效用、不同 `S`/`R` 背景和两级门控”的可审计正式训练链。

因此，`n3_train_v1.json` 和当前 `模型/n3_affect/` **不得不经修改就用于本轮正式重训**。服务器正在使用的重训代码若已修复，必须把相应 commit/diff、配置和测试结果同步回 GitHub；若尚未修复，则先完成以下代码 Gate：

1. Qwen 文本/音频/视频三路离线 extractor 与各模态 provenance；
2. K=3 数据集、三类 mask、严格过去和 current-only 精确回退；
3. emotion-only 配置（utility/VAD 为 0）；
4. dev Accuracy/Macro-F1/Weighted-F1 计算，并按 Weighted-F1 保存/恢复 best；
5. 正式 test 默认不可达且需独立显式授权；
