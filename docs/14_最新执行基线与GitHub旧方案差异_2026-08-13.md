## 1. 一句话目标

不是用一个数据集训练后直接宣称能迁移到另外两个数据集，而是用**同一套冻结的 CARMA-Affect/N3 方法和统一评估合同，在 MELD、IEMOCAP、EmotionTalk 上分别训练、验证和测试**，检查该框架能否跨数据集稳定有效。默认产出是每个数据集各自的模型/checkpoint 和结果；跨数据集零样本迁移属于额外实验，不替代三数据集内验证。

### 1.1 已解压数据的执行入口

MELD 与 IEMOCAP 的数据集专用操作细节分别冻结在 [MELD 已解压数据后续执行全流程](15_MELD_已解压数据后续执行全流程_2026-08-13.md) 和 [IEMOCAP 已解压数据后续执行全流程](16_IEMOCAP_已解压数据后续执行全流程_2026-08-13.md)。两份执行单服从本文的 Phase A/Phase B 总合同；若出现冲突，以本文为准。

**已解压不等于可训练。** `extracted` 只表示文件已落盘；在数据/媒体、manifest、严格过去、Qwen 三模态来源、数值、mask、checkpoint 和 test-deny Gate 通过前，不得标记 `training_ready`。若代码能力审计发现缺少 MELD 或 IEMOCAP 的正式 CLI，下一步必须是实现并测试缺失 Gate；不得改跑 synthetic trainer、旧 sidecar、只处理文本的入口或示例命令来冒充当前正式管线。

## 2. Phase A — Qwen 三模态管线与独立 A0/A1 CE 基线

Phase A 的目的只是在不混入完整 N3 辅助机制的情况下，先证明数据、三模态特征、严格历史、缺失回退和基础分类训练管线正确。**Phase A 通过不等于完整 N3 创新有效**，也不能替代 Phase B 的机制比较、消融与统计确认。

### 2.1 三层表示符号与形状合同

后续代码、配置、cache、checkpoint 和公式必须区分以下三层，不得再用同一个 `T/A/V` 符号混写原始输入、Qwen 隐藏表示和 N3 投影表示：

| 层级 | 冻结符号 | 含义 | 是否进入 Git |
|---|---|---|---|
| 原始模态输入 | `x_i^m` | 话语 `i` 的原始文本、波形或视频片段，`m∈{T,A,V}` | 否 |
| Qwen hidden | `e_i^m = E_Qwen^m(x_i^m)` | 冻结 `Qwen3-Omni-30B-A3B-Instruct` 对单一模态独立调用所得隐藏表示；保留各模态原始输出维度 `d_e^m` | 否；只在仓库外分路缓存 |
| N3 projected | `z_i^m = P_m(e_i^m) ∈ R^128` | 三个可训练且不共享参数的 `ModalityProjector P_T/P_A/P_V` 输出 | 仅代码/配置可提交，张量不可提交 |

批处理接口固定为：

```text
Z_current = stack(z_t^T, z_t^A, z_t^V)              # [B, 3, 128]
Z_history = stack_k,m(z_hk^m), K=3                  # [B, K, 3, 128]
current_modality_mask                               # bool [B, 3]
history_mask                                        # bool [B, K]
history_modality_mask                               # bool [B, K, 3]
same_speaker                                        # bool [B, K]
```

其中 `x` 只由数据/processor 层消费，`e` 是冻结 Qwen 的可追溯离线产物，`z` 才是 N3 关系层、情绪头和门控层的统一输入。主线要求：

- 文本、音频、视频都由冻结 Qwen3-Omni **分别调用、分别缓存、分别记录 provenance**；禁止从一次混合多模态调用中复制三个别名，也禁止用 librosa/torchvision/MM-Align 结果冒充 `e^A/e^V`；
- 每路 `e` 至少绑定 `sample_id`、模态、模型/权重 revision、processor 与预处理 SHA、输出 shape/dtype、内容 hash 和缺失原因；
- `P_m` 只改变维度，不改变样本顺序、候选轴或模态轴；任何提前把 `[K,3]` 聚合掉的实现均不合格；
- RoBERTa/DeBERTa、emotion2vec/SER-WavLM、AffectNet/FER+/AU 等情感专用编码器只作为**替代表征 baseline**：用其 `e_i^{m,spec}` 替换同模态 Qwen `e_i^m`，仍经过相同 `P_m`、`Z_current/Z_history` 接口、N3 结构、切分与预算。它们不是主模型额外叠加的组件，也不能把“移除情感编码器”写成主模型消融。

### 2.2 样本与历史合同

- 历史窗口固定 `K=3`，只允许严格过去的话语，禁止未来信息；
- 候选槽位全局固定：先取同一对话中严格过去最近 `K=3` 条，再按 oldest→newest 写入 `h_1,...,h_K`，所以 `h_K` 最近；不足 `K` 时固定**左侧 padding**，例如两条合法历史为 `[PAD,h_2,h_3]` 与 `history_mask=[0,1,1]`。禁止右 padding、阶段/数据集临场改侧或复制样本补 K；padding 的所有派生量必须先受 `history_mask=0` 屏蔽；
- 模型接口必须精确接收 `Z_current[B,3,128]`、`Z_history[B,K,3,128]` 及三类 mask；shape、dtype、候选顺序和模态顺序均须运行时断言；
- 首条话语或没有合法历史时，必须在 A1/Phase B 历史 classifier 之前**逐样本硬切独立 A0-best**并直接返回其 logits/probs，不能构造伪历史、运行空历史 classifier 或混合概率；
- 缺失模态由 mask 表达。全零向量只能作为受审计的缺失回退，不能静默当作成功提取的真实特征。

### 2.3 第一轮训练合同

第一轮目标是验证数据和三模态管线正确，不一次性启用所有 N3 辅助任务。Phase A 不是一个含糊的 emotion-only 模型，而是必须独立训练、独立选 best 的两个 CE-only 基线：A0 current-only 与 A1 plain-history：

```text
loss_A0 = emotion_classification_loss
loss_A1 = emotion_classification_loss
utility_loss_weight = 0
vad_loss_weight = 0
history_K = 3
model_selection_metric = dev Weighted-F1
test_policy = STOP_BEFORE_TEST_A
```

- 对每个话语先做无参数、mask-safe modality mean：`u_i = sum_m mask_i^m z_i^m / max(sum_m mask_i^m,1)`；
- A0 只输入 `u_t`：`logits_A0=C_A0(u_t)`；
- A1 对合法历史的 `u_hk` 再做无参数、mask-safe mean：`n_hist=sum_k history_mask_k`、`hbar=sum_k history_mask_k u_hk/max(n_hist,1)`，且仅在 `n_hist>0` 时输入独立 classifier：`C_A1([u_t;hbar;u_t⊙hbar;u_t-hbar;n_hist/K])`；
- A0 与 A1 各自训练 Projector/classifier、optimizer、checkpoint 和 lineage，分别按 dev Weighted-F1 选 A0-best/A1-best；不得把 A1 写成 A0 classifier 加一个开关；
- A1 禁止 learned history attention、关系层、state/VAD、`a_k/φ_k`、utility 和任一级 gate；所有 mean 均无参数且 mask-safe；
- 当 `n_hist=0` 时，A1 runner 在进入 `C_A1` 前硬切到独立 A0-best，直接返回其 logits/probs；禁止用零 `hbar` 运行 A1。记录 `fallback_reason=no_legal_history`、A0 checkpoint/model SHA 和 A1 source run SHA，并测试 fallback 与直接 A0 输出逐元素一致；
- 第一轮先做独立 A0/A1 `CE-only`；schema/函数签名可保留 VAD、效用与门控占位，但 Phase A runtime graph 必须不实例化或不激活 state/VAD producer、`a_k/φ_k`、utility heads、模态门和候选联合门。仅把 loss weight 设为 0、却仍让分支影响 emotion logits，不合格；
- 用 dev Weighted-F1 分别选择 A0-best 与 A1-best checkpoint，同时记录各自 dev Accuracy、Macro-F1、loss；
- Phase A 训练与 dev 验证通过后停在 `STOP_BEFORE_TEST_A`，随后只允许进入 Phase B 实现/训练，不得运行正式 test；Phase B 冻结完成后再停在 `STOP_BEFORE_TEST`；
- MELD/EmotionTalk 的 test 是独立、一次性、write-once 的最终确认阶段；IEMOCAP 则按预注册的 outer-fold held-out 角色逐折隔离并一次汇总。两类评估都只能在配置、源码、特征审计和 best checkpoint 全部冻结后单独授权。

第一轮通过后，才依次加入共享 3×3 当前—历史关系、模态级/联合级双向边际效用、两级门控、VAD/冲突等理论变量和预注册消融。这里的分阶段执行不改变最终 N3 研究目标。

Phase A 与 Phase B 只默认复用冻结、outcome-blind 的 Qwen `e` cache 合同；不得静默把 Phase A Projector、classifier、optimizer、校准器或 checkpoint 作为 Phase B 初始化。若要研究 Phase-A initialization，必须在看 dev/outer-eval 结果前登记为独立、fit-only 的变体，配置与 lineage 明确标注并与 Phase B 默认随机/冻结初始化分开报告。

### 2.4 Phase A 固定执行链

```text
单样本 T/A/V 来源与数值证明
→ 32 train / 8 dev 冒烟
→ 全量三路离线特征与 provenance 审计
→ 独立 A0 current-only CE train+dev
→ 独立 A1 plain-history CE train+dev
→ dev Weighted-F1 分别选择 A0-best / A1-best
→ STOP_BEFORE_TEST_A
```

每种模态必须有独立缓存和 provenance，至少绑定数据集/split、样本 ID、模态、Qwen model ID/权重版本、预处理版本、输出 shape/dtype、缺失 mask 和缓存/manifest 散列。禁止只保存一个无法拆分、无法证明三种来源的混合向量。

## 3. Phase B — 完整 N3 情感历史效用实验

Phase B 只能在相应数据集的 Phase A 管线 Gate 通过后进入；它是验证情感领域理论与双向效用创新的正式方法阶段，不得把 Phase A 的 Qwen 特征基线结果写成 Phase B 结果。

### 3.1 每个历史候选分别计算 3×3

对严格过去窗口中的每个候选 `h_k, k∈{1,2,3}`，分别保留 `z_{h_k}^T/z_{h_k}^A/z_{h_k}^V`，先计算当前 `z_t^T/z_t^A/z_t^V` 与该候选三种模态之间的九组**基础关系**：

```text
R_k^0 = { r_mn^0(z_t^m, z_hk^n) | m,n ∈ {T,A,V} },  k = 1,2,3
```

**禁止先将 `h_1/h_2/h_3` 聚合为一个历史向量，再只计算一次 3×3。** 候选级轴和模态级轴都必须保留到效用估计与门控阶段，以支持逐候选、逐模态归因和部分保留。

### 3.2 情绪后验、VAD 与理论变量的计算来源

情感变量必须由冻结来源或 fit-only/group-OOF 预测得到，不能从 dev/test 或 outer-eval gold 标签构造：

```text
p_i^m = softmax(H_emo^m(z_i^m))                       # 每模态情绪后验
p_i   = Fuse({p_i^m}, current_modality_mask_i)         # 话语级情绪后验
v_i^m = H_vad^m(z_i^m),  v_i = (valence, arousal, dominance)
c_i^m = Cal_m(p_i^m, quality_i^m, mask_i^m)            # 逐模态校准置信度
```

- 训练行用于下游理论变量的 `p_i/v_i/c_i` 必须来自按 dialogue/session/speaker 整组划分的 OOF producer。producer 从冻结 `e` 开始，包含状态专用 Projector、`H_emo^m/H_vad^m` 和任何可学习 calibration/confidence 模块等全部可学习上游；每个 inner fold 从冻结 `e` 独立拟合参数副本，确保产生预测的 producer 未训练该行或同组数据。不得只 cross-fit 最后一个 head；
- 上式状态 producer 的 `z_i^m` 必须由对应 inner-fit 状态 Projector 生成，不能复用已看过 held-out group gold 的 full-fit 主 N3 `z_i^m`。若架构共享 Projector，OOF sidecar 仍使用 inner-fold 参数副本，并在 schema/lineage 中显式区分 `z_main` 与 `z_state_oof`；
- dev gold 可且仅可进入隔离的 metric/model-selection evaluator，按冻结规则计算指标和选择 best；不能生成 posterior/VAD/confidence、`a_k/phi_k`、utility target 或任何训练特征。test/outer-eval gold 只可在明确授权后进入独立 write-once evaluator，授权前不可达；
- 只有存在经协议批准的连续 VAD 标注时，才允许在 inner-fit groups 内拟合 `H_vad`。否则只能使用首次训练前已经冻结版本、数值、文献/许可来源与类别顺序的外部 VAD prototype/映射，并以预测 posterior 求期望；
- 若批准的连续 VAD 监督和预冻结外部 prototype/映射均不存在，则状态必须为 `BLOCKED_VAD_SOURCE_NOT_FROZEN`。禁止执行 AI 临场从离散类别或 dev 结果编造 VAD，禁止全零/伪 target，也禁止多种来源按结果临场混用。
- `c_i^m` 必须逐模态、mask-aware 且版本化；若 `Cal_m` 可学习，其拟合、校准与 lineage 遵守相同 inner group-OOF。缺失模态的 confidence 为 unavailable 并由 mask 排除，不得填充伪置信度。
- fit gold 只允许监督 inner-fit/full-fit producer、计算 `L_emotion`，以及由未见相应 group 的 OOF counterfactual evaluator 计算 utility loss difference/target；禁止把 gold one-hot、gold 类别查表 VAD 或任何 gold-derived 值序列化为 forward 输入。dev/test/outer-eval gold 不能生成状态、置信度、理论变量或 utility target。

对 query `t` 与候选 `h_k`，理论特征 `a_k` 的最低可计算定义为：

```text
actor_inertia_k = masked(similarity(p_t, p_hk), same_speaker_k)
actor_recovery_k = masked(recovery(actor_baseline_<t, p_hk, p_t), same_speaker_k)
interaction_shift_k = distance(p_t, p_hk)             # 同/跨说话人交互转折
vad_delta_k = [v_t, v_hk, v_t - v_hk, |v_t - v_hk|]
confidence_k = [c_t^T,c_t^A,c_t^V,c_hk^T,c_hk^A,c_hk^V]
conflict_t  = disagreement({p_t^T,p_t^A,p_t^V},{c_t^m},mask_t)
conflict_hk = disagreement({p_hk^T,p_hk^A,p_hk^V},{c_hk^m},mask_hk)
conflict_delta_k = conflict_t - conflict_hk
quality_k   = modality quality/missingness
metadata_k  = [time_distance, same_speaker]
a_k         = concat(上述状态、confidence、dynamics、conflicts、metadata、quality 及可用性 masks)
```

actor inertia/recovery 只在 `same_speaker_k=true` 时有定义，跨说话人时显式 mask；其 baseline/参考窗只来自早于 `t` 的同说话人 OOF/frozen-producer 预测。`interaction_shift_k` 单独承担跨说话人候选的状态变化语义，不能冒充 actor inertia/recovery。恢复至少表达“先前偏离冻结参考状态、当前又向该参考状态回归”，不能只是把 shift 改名；无足够严格过去时用 mask 表达，不伪造值。

current 与 history 候选的跨模态冲突必须分别计算，并可带差值；每一端至少两个模态可用才计算，否则该端及其差值 mask，禁止缺失模态零向量制造冲突。上述公式、参考窗/阈值、跨模态分歧度量、confidence calibration 和质量函数必须在查看 dev 完整结果前写入版本化配置。

### 3.3 `φ_k`、真实双向效用与两级门控

- 每个候选的统一条件表示固定为 `φ_k = Phi(R_k^0, a_k, masks_k)`；它融合基础九路关系 `R_k^0`，以及 `a_k` 中的 posterior、VAD、逐模态 confidence、same-speaker actor dynamics、interaction shift、current/history conflict、时间/说话人关系、模态质量和缺失 mask。随后计算条件化关系 `R_k = Rel(R_k^0, φ_k, masks_k)`。这一顺序避免 `R_k` 与 `φ_k` 循环定义；候选轴在 `φ_1/φ_2/φ_3` 和 `R_1/R_2/R_3` 之后仍保留；
- 历史候选固定来自同一对话中的严格过去，不限制说话人，并逐候选保存 `same_speaker`；同说话人-only 历史作为预注册对照。这样说话人关系不是恒为真的常量，也不允许各数据集临场选择不同历史总体；
- 对每个 `h_k`，以 `φ_k` 和对应模态关系为条件，分别估计文本、音频、视频的模态级前向加入收益与后向删除风险，再估计该候选的联合级双向效用和不可加协同/冲突残差；
- 前向背景 `S` 与后向背景 `R` 必须是预注册的不同集合状态；禁止用同一差值换符号伪造“双向”；
- utility target 和 utility head 的训练输入都只来自 train-only/group-OOF 产物；utility target producer 也必须从冻结 `e` 起让 Projector、base classifier、counterfactual predictor 与校准器等全部可学习上游在 inner-fit groups 内独立拟合，再为 held-out group 产生预测。fit gold 只在独立 OOF evaluator 中计算 loss difference，不成为 predictor/head 输入。每条 target 必须绑定 group fold、背景 `S/R`、base/counterfactual prediction 与源码/config SHA；
- 第一级模态门控 `g_k^m = G_mod(R_k^m,φ_k,U_k^m,quality_k^m,mask_k^m)` 在候选内部按 T/A/V 决定部分保留；第二级候选门控 `g_k = G_joint(R_k,φ_k,U_k^joint,U_k^cross,{g_k^m},masks_k)` 决定该候选是否进入。候选门必须直接消费 `φ_k`，不能只经模态门间接传入；门控由此同时依赖条件化关系、情感理论特征、双向效用、质量和完整 masks，而不是互不相连的旁路；
- 对 `φ_k` 的四条直接连接必须分别执行 `no_phi_to_relation`、`no_phi_to_utility`、`no_phi_to_modality_gate`、`no_phi_to_candidate_gate` 消融与 forward 干预测试；候选联合门必须直接消费 `φ_k`，不能只通过模态门间接接收。其余输入、预算、seed 和训练规则保持一致；
- 无候选通过、无合法历史或风险不合格时，在 Phase B history fusion/classifier 之前逐样本硬切到与该数据集/split/seed 绑定的独立 A0-best checkpoint，直接返回 A0 logits/probs；不得运行 Phase B 空历史、不得与 N3 概率混合。receipt 必须记录 fallback reason、A0 checkpoint/model SHA、Phase B source run SHA，并验证 fallback 与直接 A0 输出逐元素一致；
- 完整 N3 采用至少 5 个随机种子、按 dialogue/session/speaker 分组的配对 95% CI，以及预注册的完整强基线和组件消融。只有真实情感分类指标与合取成功门通过，才能支持完整 N3 有效性主张。

### 3.4 三数据集与 test 合同

MELD、EmotionTalk、IEMOCAP 使用同一冻结框架、接口、阶段顺序与评估原则，但在各自合法切分中**分别训练、验证和评估**，默认产生三个数据集各自的 checkpoint；不合并三个数据集训练，也不默认用一套权重零样本跑三个数据集来替代数据集内验证。MELD/EmotionTalk 的官方 test 需要独立授权并 write-once。IEMOCAP 默认采用预注册的外层 Session 五折交叉验证：每个 Session 在一个 outer fold 中作 test，同时会在其他 folds 中作 train/dev，因此只能声称 fold 内 held-out，不能声称五个 Session 在整个开发期全局从未使用；所有外层 fold 规则、结构和统计合同须预先冻结，结果不得逐折回流修改方法。

## 6. MELD：旧运行问题与重新训练 Gate

### 6.1 旧运行仅作诊断

旧运行曾得到：dev Accuracy `0.5469`、Macro-F1 `0.3295`、Weighted-F1 `0.5042`；test Accuracy `0.5808`、Macro-F1 `0.3322`、Weighted-F1 `0.5418`。这些数字必须标注为 `invalid_preliminary_run`，不得进入论文主结果或反向指导超参数。

判无效的原因：

- Qwen 只处理了文本；音频来自 librosa 的 MFCC/梅尔统计，视频来自 torchvision 的颜色/空间统计；
- 视频全零：train `9477/9989`、dev `1004/1108`、test `2501/2610`，总计 `12982/13707 = 94.71%`；
- 文本表示经过随机且冻结的 `2048→256 Linear`，并非可靠训练投影；
- VAD 使用全零伪 target 却设置了非零权重 `0.1`；utility 没有真实 target 却设置了非零权重 `0.2`；
- best checkpoint 按 dev loss，而不是冻结的 dev Weighted-F1；
- checkpoint 信息不完整，且训练结束后自动读取并评估了 test。

### 6.2 Phase A 重训顺序（不得跳步）

```text
G0 数据与媒体清单通过
→ G1 单个样本的 Qwen 文本/音频/视频均成功且非伪零
→ G2 32 个 train + 8 个 dev 冒烟通过
→ G3 全量离线特征抽取与审计通过
→ G4 独立 A0/A1 CE 正式 train + dev，分别按 dev Weighted-F1 保存 best
→ STOP_BEFORE_TEST_A
→ Phase B 实现、train+dev、基线/消融与统计冻结
→ STOP_BEFORE_TEST
→ 独立冻结审计与人工授权
→ G5 一次性正式 test
```

各 Gate 最低要求：

- `G0`：样本 ID、dialogue、speaker、turn、label、文本、音频、视频一一对齐；train/dev/test 不交叉；
- `G1`：分别输出 T/A/V 的 shape、dtype、finite 比例、范数、mask、媒体时长及模型标识；三路均能独立证明来自 Qwen；
- `G2`：完成 forward、backward、optimizer step 和 dev inference；loss 有限；GPU 无 OOM/illegal access；保存并可重新加载 checkpoint；
- `G3`：逐 split 报告总数、成功数、缺失数、全零数、NaN/Inf 数、维度、重复/错位数。任何异常都必须给出样本 ID 清单和原因；
- `G4`：配置、随机种子、类别顺序、class weights、源码版本、Qwen 模型/权重标识、特征 manifest/hash 与 best 指标写入 checkpoint/receipt；
- `G5`：test 输出 write-once；只在独立授权后运行一次，不再据此调参。
