> 状态：IEMOCAP 专用执行单（ACTIVE，尚未完成代码实现）
>
> 适用对象：已经从 USC 官方渠道取得授权、官方归档校验通过并完整解压 IEMOCAP 的服务器执行者或服务器 AI
>
> 执行边界：本文规定从“已解压”到 Phase A、Phase B 以及预冻结的外层 Session 五折 OOF（out-of-fold）汇总。**主协议是 nested outer-Session 5-fold cross-validation，不是另有一个全局从未观察的官方 test。**每个外层折的 held-out Session 只由该折的独立 evaluator 评估；同一 Session 会在其他折中承担 train 或 dev，因此不得称为“全局未观察 test”。
>

## 1. 最终目标

在不把 IEMOCAP 与 MELD、EmotionTalk 合并训练的前提下，使用同一冻结的 N3 两阶段框架，在 IEMOCAP 上独立完成：

1. 四分类标签、Session 五折、时间戳媒体对齐和严格过去历史 manifest；
2. 将原始文本、句级音频和时间戳视频片段分别送入冻结的 `Qwen/Qwen3-Omni-30B-A3B-Instruct`，离线缓存分模态 hidden `e` 及完整 provenance；
3. 由每个外层折独立训练的 Modality Projector 把 `e` 投影为 `z`；只有 `z`（以及允许的 mask/时间/说话人/质量控制量）可以进入下游模型；
4. Phase A 完成不启用情感理论、效用和两级门控的 emotion-only 管线基线；
5. Phase B 使用 train-only/group-OOF 情绪后验与 VAD 头构造情感状态和动力学 `phi_k`，再完成逐候选 3×3、双向效用与两级门控；
6. 至少 5 seeds 的 train/dev 结果与完整审计包；
7. 在五个外层 held-out Session 上产生预冻结、逐折隔离的 OOF 预测，并只在五折完成后汇总；不得根据某折 held-out 结果修改任何后续折；
8. 如需“真正从未观察的最终确认”，必须另找没有参与本五折任何开发的独立数据集/新封存分区，且与本主协议互斥，不能把同一五个 Session 再包装成一次性 test。

默认产出是 IEMOCAP 自己的 checkpoint 和结果，不是把 MELD 模型直接零样本搬到 IEMOCAP，也不是把三个数据集拼在一起训练。

## 3. 固定的数据与标签协议

### 3.1 数据来源与目录变量

执行说明只使用占位变量，不把服务器绝对路径提交到仓库：

```text
<REPO_ROOT>       Git 仓库根目录
<IEMOCAP_ROOT>    已解压 IEMOCAP 根目录，位于仓库外
<PRIVATE_ROOT>     私有 manifest、特征、checkpoint、日志和逐样本错误清单根目录
<QWEN_ROOT>       本地 Qwen3-Omni 权重目录，位于仓库外
<PUBLIC_ROOT>     只存聚合 receipt/指标且允许审查的输出目录
<DOWNLOAD_ROOT>   任何官方下载器的显式外部目标目录，禁止默认下载到 Git 工作树
```

不得把账号、密码、token、授权邮件、服务器地址或上述变量展开后的真实绝对路径写入配置、日志摘要或 Git 提交。任何 downloader 必须要求显式 `DOWNLOAD_ROOT`，先验证 `realpath` 位于仓库外再写入；Qwen 推理必须使用固定本地 snapshot，并在执行进程中拒绝网络回退/远程代码漂移。

### 3.2 四分类映射

固定模型标签顺序：

```text
0 = angry
1 = happy
2 = sad
3 = neutral
```

固定原始标签映射：

| IEMOCAP 原始代码 | 模型标签 | 动作 |
|---|---|---|
| `ang` | `angry` | 保留 |
| `hap` | `happy` | 保留 |
| `exc` | `happy` | 与 `hap` 合并 |
| `sad` | `sad` | 保留 |
| `neu` | `neutral` | 保留 |
| `fru`、`fea`、`sur`、`dis`、`xxx`、`oth` 或其他代码 | 无 | 从四分类任务排除，但必须按原始代码报告数量 |

只解析官方 utterance-level 共识/最终标签行。不得把 individual annotator 投票行重复展开成多个训练样本，也不得用模型预测替代缺失标签。

### 3.3 `5531` 的正确用法

常用四分类协议的参考计数为：

| 类别 | 参考数量 |
|---|---:|
| angry | 1,103 |
| happy（`hap+exc`） | 1,636 |
| sad | 1,084 |
| neutral | 1,708 |
| 合计 | 5,531 |

`5,531` 是**数据漂移哨兵**，不是为了凑数而执行的无条件硬等号。新协议必须显式写：

1. 立即停止进入特征抽取和训练；

3. 检查数据版本、重复 ID、解析表达式、共识标签选择和排除规则；
4. 若差异有合法来源，以书面 protocol amendment 记录原因、修改协议版本并重新生成哈希；

### 3.4 固定 Session 五折

| fold | train | dev | outer-eval（该折 held-out） |
|---|---|---|---|
| 1 | Session3、Session4、Session5 | Session2 | Session1 |
| 2 | Session4、Session5、Session1 | Session3 | Session2 |
| 3 | Session5、Session1、Session2 | Session4 | Session3 |
| 4 | Session1、Session2、Session3 | Session5 | Session4 |
| 5 | Session2、Session3、Session4 | Session1 | Session5 |

固定约束：

- 每折 train/dev/outer-eval 的 Session 集合两两不交叉；
- 每个 Session 恰好作为 outer-eval 一次、dev 一次、train 三次；
- Session 隔离同时提供 speaker 隔离；任何同一 speaker/session 不得跨同一折的 train/dev/outer-eval；
- 切分只由 Session 决定，不能读取标签分布或性能后修改；
- 开发期间每折只能训练 train、用该折 dev 选 best；该折 outer-eval loader 默认不可达；
- 五个 outer-eval 角色只能在协议完全冻结后作为一个批次执行和汇总；不得看完一折结果后修改模型再继续。所有访问必须按 `(fold_id, role)` 记账；同一 Session 在其他折作 train/dev 不构成该折泄漏，但也意味着它不是全局未观察 test。

### 3.5 对话级 AVI 的时间戳切段

IEMOCAP 的句级音频通常已有独立 WAV，而视频主要是完整对话 AVI/DivX。视频处理必须采用以下合同：

1. 从官方转写中解析每个 utterance 的 `start_sec` 和 `end_sec`；
2. 用 `dialogue_id` 确定唯一的对话级 AVI 候选；
3. 用同一话语的 `[start_sec, end_sec]` 从对话 AVI 解码视频片段或确定性采样帧；
4. 句级音频来自与 `utterance_id` 精确对应的 WAV，不从对话 AVI 的音轨冒充句级音频；
5. 不使用句级 WAV 自身的 0 起点时长去替代对话视频时间轴；
6. 若同一对话存在多个视角/AVI 候选，必须先冻结 `video_source_policy`，记录候选数、选中视角/文件相对引用和选择原因；禁止抽取过程中静默切换；
7. 若没有预注册的人脸/说话人跟踪协议，默认保留完整画面，不能临时根据标签或结果挑人物 crop；
8. 记录视频源哈希、容器/编解码器、时长、帧率、时间戳、实际解码区间、采样策略和解码器版本；
9. 仅“AVI 文件存在”不算通过；必须证明目标区间可解码、得到非空有效帧且不是全黑/恒定伪特征。

时间容差、前后 padding、目标采样帧数/FPS 和多视角规则必须进入版本化配置。若尚未冻结，不得由代码写一个不可见默认值继续执行。

### 3.6 严格过去 `K=3` 与三类 mask

本执行单固定历史规则为：

```text
same Session
AND same dialogue
AND history.start_sec/order strictly earlier than query.start_sec/order
take the most recent at most 3 candidates
store oldest -> newest within the selected K slots
```

禁止当前话语、自指、未来话语、同时间未定序话语、跨对话或跨 Session 历史。每个样本必须生成：

- `current_modality_mask`，形状 `[3]`，顺序为 T/A/V；
- `history_ids`，长度 3，padding 位置使用空 ID；
- `history_mask`，形状 `[3]`；
- `history_modality_mask`，形状 `[3,3]`，候选轴 × T/A/V；
- `same_speaker`，形状 `[3]`，逐候选记录是否与 query 同说话人；
- batch 后对应形状 `[B,3]`、`[B,3]`、`[B,3,3]`。

没有合法历史的样本必须精确回退 current-only。不能构造伪历史、复制当前话语、用全零向量冒充成功历史，或用另一个 history checkpoint 的空输入近似 current-only。

### 3.7 冻结 Qwen `e`、fold-local Projector `z` 与 N3 输入边界

本文固定以下数据流，任何实现和流程图都必须与其一致：

```text
原始输入 x_t^m / x_hk^m（m ∈ {T,A,V}, k=1..3）
  → 冻结 Qwen3-Omni 分模态编码与冻结 pooling
  → 离线 hidden cache e_t^m / e_hk^m + provenance
  → 对每个 outer fold 独立训练的 Modality Projector P_f^m
  → z_t^m / z_hk^m = P_f^m(e)
  → Phase A emotion-only 或 Phase B 的 phi_k、逐候选 3×3、效用、门控与分类器
```

边界如下：

- `x` 是原始文本、句级 WAV 或按转写时间戳从对话 AVI 解码的片段；原始 `x` 不直接进入 N3；
- `e` 是冻结 Qwen 的分模态 hidden，T/A/V 必须分别缓存、分别记录 model revision、weights manifest、processor、pooling、shape、dtype、输入内容 hash 和 cache hash；不可拆分的混合向量不合格；
- `e` 可由 outcome-blind producer 对各 role 离线生成，但不得携带标签、情绪后验、VAD 或任何由标签推导的字段；
- `P_f^T/P_f^A/P_f^V` 是可训练且 fold-local 的 Projector。每折只用该折 train 梯度更新、用该折 dev 选 checkpoint；不得把其他折 Projector、optimizer/RNG 状态或投影后的 `z` 当作全局共享 cache；
- `z` 才是 emotion head、`phi_k`、关系、效用、门控和最终分类器的表示输入。任何旁路把原始 `x`、gold label、gold-derived VAD 或全局拟合状态直接送入 N3 都是泄漏或架构违约；
- Phase A 与 Phase B 可共享同一冻结 `e` cache 合同，但必须使用各自独立、可追溯的 fold-local checkpoint 与配置。Phase A 的 Projector/checkpoint 不得被静默当作 Phase B 的预训练初始化；若要复用，必须事先作为单独、冻结且各折 train-only 的实验变体登记。

### 3.8 情绪状态头、VAD 与 `phi_k` 的合法来源

Phase B 不能把“情感理论”只写成文字。它必须实现 fold-local 状态 producer，并为每个 current/history 模态输出预测情绪后验 `p^m(y|z)`、置信度以及 VAD 状态。来源固定如下：

| 变量 | 合法来源 | 禁止来源 |
|---|---|---|
| 模态情绪后验 | 在当前 outer fold 的 train 上训练的情绪头；train 行必须使用按 dialogue 分组的 OOF 预测，dev/outer-eval 只用冻结头前向预测 | 当前或历史 gold label 的 one-hot；在同一行上拟合后再预测自身 |
| VAD | 若有经协议批准的连续标注，只在 fold train 拟合 VAD 头；否则用预测情绪后验对预先冻结、版本化的四类 VAD prototype 求期望 | dev/outer-eval 标签；执行 AI 临时选择 prototype；把 gold 类别直接查表后作为输入 |
| 惯性 | query 与候选 `h_k` 的预测后验/VAD 相似性，结合 `same_speaker[k]` 和冻结时间衰减 | 用 gold 标签是否相同代替 |
| 转折 | current 与 `h_k` 的预测后验 JSD、预测类别变化概率、VAD 有符号差 | 用真实标签变化直接输入 |
| 恢复 | current 预测状态相对仅由严格过去、同说话人状态构成的 fold-local 基线的回归程度；无同说话人基线时 mask | 用未来话轮、query gold 或全数据集说话人均值 |
| 跨模态冲突 | 同一话轮 T/A/V 预测后验的两两 JSD、VAD 方向差与置信度分歧 | 用三模态最终 gold 一致性或人工结果筛选 |
| 时间/说话人/质量 | manifest 的时间差、`same_speaker[k]`、预注册媒体/模态质量字段 | 将这些控制量冒充情感状态或从标签反推质量 |

对 outer fold `f`，train 内部状态 producer 必须采用按 `dialogue_id` 分组的 inner cross-fitting：同一 dialogue 的行不得同时出现在某个 inner model 的 fit 与 prediction 部分。这里的 producer 包含从 `e` 开始的**全部可学习上游**——状态专用 Projector、情绪/VAD heads 和校准器；不能只把最后一个 head cross-fit，却让其 Projector 预先看过全部 fold-train 标签。每个 inner split 都须从冻结 `e` 独立拟合 producer，只为 held-out dialogues 产生预测。所有 train 行及其 history（与 query 同 dialogue）都由未见过该 dialogue 的 inner producer 生成 OOF 后验/VAD。

该折 dev 和 outer-eval 使用在完整 fold-train 上拟合、随后冻结的 full-train state producer 前向预测。主 N3 的 Projector 与 state producer 的 Projector 若不共享参数，须在 schema 中区分；若设计为共享，OOF sidecar 仍必须来自 inner-fit 参数副本，训练行不得改用看过自身标签的 full-train 副本。Gold 标签只可作为 inner-fit/full-fold-train 的监督损失输入和 fit-only utility target 的上游依据，不得成为 forward 特征。不得用 dev/outer-eval gold 训练、校准、选择 prototype 或构造 `phi_k`。如果情绪头需要校准，校准器也必须遵循 train-only/group-OOF，并写入 lineage。

若没有经协议批准的连续 VAD 标注或尚未冻结 VAD prototype 的数值、文献/版本来源和类别顺序，状态为 `I8_BLOCKED_VAD_SOURCE_NOT_FROZEN`；执行 AI 不得自行编造 prototype。惯性和恢复默认只在 `same_speaker[k]=true` 时有效，否则相应变量置为受审计的 masked value；跨说话人情形是否定义为“交互转折”也必须预先冻结，不能看 dev 结果后改变语义。

对每个候选 `h_k` 单独构造：

```text
phi_k = concat(
  predicted affect state of current and h_k,
  inertia_k, transition_k, recovery_k,
  current/history cross-modal conflict,
  delta_t_k, same_speaker_k,
  modality quality and availability masks
)
```

`phi_k` 必须带候选轴 `[B,K,...]`，不能在进入关系与门控前对 `k` 求均值。完整 Phase B 中，同一个 `phi_k` 必须显式连接到三处：

1. 每个 `h_k` 的当前模态 × 历史模态基础 3×3 关系 `R_k^0`，以及由同一 `phi_k` 条件化后的关系 `R_k`；
2. 该候选的模态级与联合级双向效用估计；
3. 先模态级、后候选联合级的两级门控。

建议的关系合同为：

```text
r_k^{0,i,j} = g_base(z_t^i, z_hk^j,
                     z_t^i ⊙ z_hk^j,
                     z_t^i - z_hk^j,
                     modality_pair_id(i,j))
R_k^0 = {r_k^{0,i,j} | i,j ∈ {T,A,V}}
R_k   = g_condition(R_k^0, phi_k, masks_k)
```

这一顺序先由 `z` 得到基础九路关系，再用 `phi_k` 条件化，避免 `R_k` 与 `phi_k` 循环定义。`phi_k` 只计算但未进入 forward、只进入一个日志头、或被提前聚合，均不能声称“情感理论已融入 N3”。

| 文本 | `transcript_ref`、`transcript_present`、`transcript_source_sha256` |

每折 outer-eval 标签必须按 `(fold_id, role=outer_eval)` 存入与该折 train/dev 输入物理分离的 capability/artifact。train/dev runner 不应接收 outer-eval label 路径，也不得枚举评估输出目录。这里的隔离是逐折隔离，不是把五个 Session 全局封存。

公开 receipt 只包含：

- 协议、代码 commit、配置和 manifest 的 SHA-256；
- train/dev 的 Session/role/类别聚合计数；outer-eval 在正式汇总前只公开样本总数和结构审计，不提前公开类别分布；
- 文件存在、解码成功、缺失、重复、零字节、时间越界的聚合计数；
- T/A/V 成功、缺失、全零、NaN/Inf、维度漂移的聚合计数；
- `e` cache、fold-local Projector/状态头、group-OOF 覆盖和 `phi_k` schema 的版本/hash 与不泄露标签的聚合审计；
- 历史深度 0/1/2/3 的聚合计数和 mask 审计结果；
- Gate 的 `PASS/FAIL/BLOCKED`、首个失败原因和时间；
- 不含逐样本 ID、文本、标签、路径、媒体、特征或预测。

```text
I0 源码、协议、环境和 outer-fold 能力隔离

→ I2 四分类标签/转写/WAV/AVI 私有 manifest
```

任何 Gate 失败都必须停止。不能跳过失败 Gate 去“先跑一下训练看看”。

## 6. 各 Gate 的执行要求

### I0 — 源码、协议、环境和 outer-fold 能力隔离

执行动作：

1. 记录 Git branch、commit、tree、dirty 状态；有未解释改动时不得建立可确认运行；
2. 确认原始数据、Qwen 权重、私有输出均在仓库外；
3. 生成新的 IEMOCAP 专用 protocol/config，不原地篡改旧 v1 历史合同；
4. 固定四分类顺序、五折映射、历史规则、时间戳/视频策略、Qwen model ID、loss 权重和 outer-eval policy；
5. 固定 Python、PyTorch、CUDA、transformers/Qwen remote code、ffmpeg/ffprobe 或所选解码库的版本；
6. 检查 Qwen 权重快照完整、无 `.incomplete`，记录 snapshot/revision 和权重文件哈希清单；
7. 保证每折 outer-eval runner 默认不可调用、输出路径不存在且 write-once，并按 `(fold_id, role)` 记录访问；
8. 运行现有测试作为回归基线，但不得把合成测试通过写成 IEMOCAP 数据已通过。

还必须在 I0 冻结或明确列为 `BLOCKED`：三模态 processor/pooling 与 `e` schema、Projector 结构和是否在 Phase A/B 间复用、状态 producer 的 inner group-cross-fitting 规则、VAD 连续标注或 prototype 来源、`phi_k` 字段/跨说话人语义，以及 optimizer、LR、batch、patience 等科学设置。执行 AI 不得在看到 dev/outer-eval 结果后自行补选这些设置。

在接触真实数据前，必须先用纯合成五折 fixture 运行 test-access canary：为每折 outer-eval label 放置带唯一随机内容的读取 trap，确认 train/dev parser、extractor 和 trainer 不枚举、不打开、不 hash 该 artifact，且访问计数均为 0。canary 失败即 `I0_FAIL_CAPABILITY_BOUNDARY`。该测试不得把真实 IEMOCAP outer-eval label 路径传入开发进程。

真实执行时采用能力分离：数据 custodian 进程持有完整 `fold_roles` 与 outer-eval labels；开发进程只获得本折 train/dev label capability 和无标签媒体/feature capability；outer evaluator 只获得一个 fold 的冻结 checkpoint、无标签输入与该折 outer-eval label capability。开发进程不得兼任 custodian，也不得接收可推导其他 folds outer-eval labels 的路径或对象。

PASS：协议与环境 receipt 齐全；所有路径边界正确；任一 outer-eval 角色未访问；旧/新合同不冲突。

FAIL/BLOCKED：工作树来源不明、路径进入 Git、协议未版本化、环境不可复现、Qwen 权重不完整，或任一 outer-eval 入口默认可达。

输出：`I0_environment_and_protocol_receipt.json`（私有完整版本 + 可公开聚合版本）。

### I1 — 解压目录与媒体库存

已知参考事实：官方归档 17,695,884,032 字节，MD5 `521be1e5eec425ae21fdc27c763ca813`；此前 `gzip -t` 和完整解压通过，Session1–Session5、句级 WAV、对话级 AVI/DivX 存在，零字节为 0。此处仍须由当前运行环境重新确认数据根，不能只引用聊天截图。

执行动作：

1. 只读定位唯一数据根及 Session1–Session5；
2. 分 Session 统计文件、目录、WAV、AVI/DivX、转写、EmoEvaluation 和零字节数量；
3. 单独统计并忽略 `._*` 与 `.DS_Store`，不需要删除；
4. 检查大小写冲突、重复相对路径、坏软链接和数据根嵌套错误；
5. 对所有进入四分类 manifest 的句级 WAV 和对应 AVI 目标时间区间做全量可解码性验证；额外抽检只能用于画面内容质量诊断，不能用来替代全量解码 Gate；
6. 不读取标签内容来决定 Session 或文件是否保留。

PASS：恰有 Session1–Session5；必需目录存在；无零字节/坏链接；媒体可探测；未发现无法解释的缺失。

FAIL：缺 Session、多余伪 Session、文件根定位不唯一、媒体不可读、零字节或目录结构与官方 release 明显不符。

输出：`I1_inventory_private.json` 与 `I1_inventory_aggregate.json`。

### I2 — 四分类标签、转写、WAV、AVI 私有 manifest

执行动作：

1. 实现并测试 IEMOCAP parser；
2. 只解析官方最终/共识标签行，生成唯一 `utterance_id`；
3. 按固定映射保留 `ang/hap/exc/sad/neu`，完整报告排除标签；
4. 从官方转写解析 utterance 文本和起止时间；
5. 交叉核验 ID 推导的 Session/dialogue/speaker 与目录/标注来源；
6. 将每条保留话语对齐到唯一句级 WAV 和唯一冻结策略下的对话 AVI；
7. 用探测结果验证 `0 <= start_sec < end_sec`，视频区间在允许容差内；
8. 对每个目标区间执行最小解码检查；
9. 生成私有逐样本 manifest 和 aggregate receipt；
10. 对 5,531 及参考分类计数执行漂移审计，不为凑数改数据。

PASS：保留 ID 唯一；每条只有一个最终标签；标签/文本/时间/WAV/AVI 一一对齐；计数符合参考或已有经过版本化批准的差异说明；视频片段可解码。

FAIL/BLOCKED：重复 ID、同一 ID 多标签、时间非法、WAV/AVI 错配、视频候选策略不唯一、解析器把 annotator 行当样本，或计数漂移尚未解释。

输出：custodian 私有 row manifest、按 `(fold_id, role=outer_eval)` 物理分离的 label capabilities、`I2_manifest_aggregate.json`。

### I3 — Session 五折、严格过去 K=3 与 masks

执行动作：

1. 纯粹按固定表赋予每个样本 5 个 fold role；
2. 审计每折 train/dev/outer-eval Session 集合；
3. 证明同一折内 dialogue、speaker、Session 不跨 role；
4. 按同 Session+dialogue+严格过去规则构造最近最多 3 条历史，不限制说话人，并逐候选保存 `same_speaker`；
5. 固定 history 槽位为 oldest→newest，padding/mask 一致；
6. 审计 future/self/cross-dialogue/cross-session 泄漏为 0；
7. 报告 history depth 0/1/2/3 聚合计数；
8. 对无历史和缺模态样本执行 current-only 回退合同测试；
9. outer-eval rows 可以有不含标签的结构性 hidden manifest，但相应折的 train/dev runner 不得接收 outer-eval labels。

PASS：五折映射精确；按 `(fold_id, role)` 计量的泄漏计数全部为 0；三 masks、`same_speaker`、媒体 availability 和 padding 一致；无历史回退精确。

FAIL：任何同一折内跨 role/session 泄漏、未来历史、自指、非确定排序、mask/`same_speaker` 与特征不一致，或为补 K 复制样本。

输出：`I3_fold_and_history_private.json` 与 aggregate receipt。

### I4 — 单样本原始 `x` 到冻结 Qwen 分模态 hidden `e` 证明

执行前提：Qwen3-Omni 三模态 extractor 已实现并有合成测试；不能使用当前仅文本的 `encoders.py` 冒充完成。

固定选择 fold1 的 train 角色中一条 T/A/V 均存在且含合法历史的样本；不得为修 extractor 查看 dev 或 outer-eval 输入。分别运行：

- 当前文本；
- 当前句级 WAV；
- 当前话语时间戳对应的视频片段；
- 至少一个历史候选的 T/A/V。

每一路从原始 `x` 经过冻结 Qwen 和冻结 pooling 得到对应 hidden `e`。本 Gate 不训练 Projector，也不把 Qwen 输出称为 `z` 或最终情感预测。每一路必须输出并写入 receipt：

```text
model_id / revision / weight-manifest SHA
preprocess and extractor version
processor class / pooling policy / pooling config SHA
sample role（不能含真实 ID 的公开版本）
modality
input media duration or text token count
e output shape and dtype
finite count / NaN / Inf
L2 norm / all-zero status
availability mask
cache key and cache SHA
```

PASS：T/A/V 原始输入分别调用冻结 Qwen、分别缓存 `e`、分别有 provenance；pooling 已冻结；shape 固定；finite=100%；非缺失输入不得得到静默全零；视频确实来自时间戳片段；cache 不含标签、VAD、`phi_k` 或 Projector 输出。

FAIL：Qwen 只处理文本、A/V 来自旧统计特征、只保存不可拆分混合向量、把 Projector `z` 冒充冻结 cache `e`、pooling 未冻结、输出全零/NaN/Inf、OOM/illegal access、视频时间轴错误或 provenance 不全。

输出：`I4_single_sample_private.json` 与不含 ID/路径的 aggregate receipt。

### I5 — 单折 32 train / 8 dev 冒烟

只选择一个预注册开发折，从其 train 取 32 条、dev 取 8 条。抽样规则必须固定 seed，不能按标签或“容易解码”挑样本；若抽样遇到缺模态，必须按真实 mask 处理。

本 Gate 必须证明 `e → P_f^m → z`：为 T/A/V 建立独立的可训练 fold-local Projector，只让 32 条 train 参与梯度更新，8 条 dev 仅前向与选 best。缓存 `e` 必须保持只读；Projector 参数、optimizer/RNG 和 `z` 只属于该 smoke fold/checkpoint，不得写回全局 cache。Phase A 的分类路径只允许使用 `z`、mask 和预注册基础融合；不得实例化情绪后验/VAD 状态 producer、`phi_k`、双向效用或两级 N3 门控。

固定 Phase A：

```text
loss = emotion_classification_loss
num_classes = 4
label_order = [angry, happy, sad, neutral]
history_K = 3
utility_loss_weight = 0
vad_loss_weight = 0
affect_state_phi_enabled = false
n3_utility_and_two_level_gate_enabled = false
model_selection_metric = dev Weighted-F1
outer_eval_label_and_metric_access = forbidden_during_development
```

必须验证：dataset 读取只读 `e`→collate→Projector 得到 `z`→Phase A forward→backward→optimizer step→dev inference→指标计算→checkpoint save→新进程 reload→同输入推理。还须覆盖：Qwen 参数无梯度且 hash 不变、Projector 至少一个参数更新、首条话语、history depth 0/1/2/3、缺失模态、全零/NaN fail、mask shape、outer-eval-deny。

PASS：loss 和梯度有限；Qwen/`e` 不变且 Projector 至少一个参数更新；指标可计算；best checkpoint 能重载；GPU 无 OOM/illegal access；outer-eval 标签/指标读取次数为 0。

FAIL：当前 `SyntheticSixWayDataset` 被当真实数据、类别仍为 7、原始 `x` 绕过 `e→z` 边界、Qwen 被微调、Projector 跨 fold 共享、Phase A 启用了 `phi_k`/utility/VAD/N3 门控、history 被提前聚合、checkpoint 不可重载，或任何 outer-eval 标签/指标访问。

输出：`I5_smoke_receipt.json` 与 smoke checkpoint（私有、不得进 Git）。

### I6 — 全量三路冻结 Qwen hidden `e` 与 provenance

执行动作：

1. 依据冻结 row manifest，把全部允许角色的原始 T/A/V 分别送入冻结 Qwen 并提取 hidden `e`；
2. `e^T/e^A/e^V` 三路物理或逻辑独立缓存，保留同一 `sample_id` 的对齐哈希；
3. 当前与每个历史候选共用同一 extractor 版本和缓存规范；
4. 支持断点续传，但已成功且哈希匹配的 cache 不重复覆盖；
5. 失败记录可重试，但重试次数、错误类型和最终状态必须写入私有审计；
6. 不因特征失败删除训练样本。主协议对目标四分类样本采用零缺失容忍：任何 T/A/V 缺失、解码失败或特征失败都使 I6 `BLOCKED`；只有在看到 dev/outer-eval 结果前提交并冻结 protocol amendment，才可启用明确的缺失模态策略，不能由执行 AI 临场决定；
7. 私有审计按 fold/role/modality 报告 total、success、missing、decode-fail、all-zero、NaN/Inf、dimension-drift、duplicate-cache-key 和 alignment-mismatch；公开版本不得提前给出 outer-eval 类别计数；
8. hidden manifest 绑定数据 manifest、Qwen 权重、processor、分模态 pooling、代码、预处理、媒体解码器和 `e` schema 哈希；cache 中严禁出现标签、预测情绪后验、VAD、`phi_k`、Projector 参数或 `z`。

PASS：目标样本三路 `e` 全部成功，shape/dtype 一致且 finite；缺失、解码失败、全零、重复、错位均为 0；cache 可全量按 manifest hash 核验并按预注册比例重载抽检；Qwen/processor/pooling 身份固定且 cache outcome-blind。

FAIL：大面积视频失败、全零率异常、NaN/Inf、维度漂移、T/A/V 错位、缓存覆盖导致谱系丢失，或 test 标签进入 extractor。

输出：私有三路 `e` cache、private hidden manifest、`I6_feature_aggregate.json`。

### I7 — Phase A 五折 train+dev 与第一次停止

每折从同一冻结、outcome-blind 的 Qwen `e` cache 读取输入，但独立初始化并训练 `P_f^T/P_f^A/P_f^V` 和 Phase A emotion-only 分类头。只有该折 train 参与梯度更新，该折 dev 做 early stopping/best 选择。禁止调用该折 outer-eval。各折 Projector、进程、checkpoint、optimizer/RNG 状态和缓存索引必须隔离；不得把其他折中包含该 Session 的 Projector、checkpoint、投影后 `z` 或统计带入本折。

Phase A 仅验证 `x→e→z→emotion-only` 数据和分类管线。它可以保留 current/history 结构及精确 current-only fallback，但 `phi_k`、情绪动力学变量、utility supervision、双向效用和两级 N3 门控必须关闭；`utility_loss_weight=0`、`vad_loss_weight=0`。因此 Phase A 通过不能证明情感理论或完整 N3 有效。

每折至少记录：

- fold、seed、train/dev Session；
- train/dev 样本与类别聚合计数；
- epoch loss、dev Accuracy、Macro-F1、Weighted-F1；
- best epoch 与 best dev Weighted-F1；
- config/source/Qwen hidden manifest SHA；
- 三个 Projector 的结构、初始化、checkpoint SHA，以及 Qwen 参数未进入 optimizer 的证据；
- checkpoint SHA 和 reload 验证；
- `(fold_id, role=outer_eval)` loader/label/metric access = 0。

五折 dev 结果可以汇总为管线健康证据，但 Phase A 不能被写成完整 N3 创新已经有效。

PASS：五折均完成 train+dev；best 依据统一；checkpoint roster 完整；没有 outer-eval 访问；公开结果只含允许的聚合指标。

FAIL：按 dev loss 而非 Weighted-F1 选 best、折间规则不一致、跨折复用训练状态、只跑一折就宣称完成、outer-eval 自动运行，或 checkpoint/receipt 不一致。

Gate 结束必须创建不可覆盖的 `STOP_BEFORE_TEST_A` marker，并停止进程。输出：Phase A 私有 checkpoints、聚合 dev 报告、freeze manifest。

### I8 — Phase B 完整 N3 train+dev、消融与最终停止

只有 I0–I7 全部 PASS 后才进入。Phase B 必须实现而不是只在图里描述：

1. 从冻结 `e` 读取输入，并为每个 outer fold 独立训练 Projector 得到 `z_t^m/z_hk^m`；原始 `x`、gold label 或全局拟合状态不得旁路进入 N3；
2. 在该折 train 内按 `dialogue_id` group cross-fitting 生成每一 train 行的 OOF 模态情绪后验与 VAD；每个 inner producer 必须从冻结 `e` 独立拟合其状态 Projector/head/校准器，不能让可学习上游先看完整 fold-train；dev 使用完整 fold-train 拟合后冻结的状态 producer 预测。所有 inner split、模型、校准器、prototype 和 row-level producer lineage 必须可审计；
3. 从预测状态而非 gold label 构造每个候选独立的 `phi_k`：VAD、惯性、转折、恢复、current/history 跨模态冲突，以及时间间隔、`same_speaker[k]`、模态质量/mask；
4. 对每个 `h_k, k=1..3` 分别计算 `z_t^T/z_t^A/z_t^V × z_hk^T/z_hk^A/z_hk^V` 的基础 3×3 `R_k^0`，再显式输入同一 `phi_k` 得到条件化 `R_k`；禁止先聚合三条历史或先消掉候选轴；
5. 同一 `phi_k` 还必须显式进入该候选的模态级、联合级真实双向边际效用；前向背景 `S` 与后向背景 `R` 必须不同；
6. 同一 `phi_k` 和效用结果必须进入先模态级、后候选联合级的两级门控；任何失败或无合法历史必须精确回退 current-only；
7. utility target 只能由该 outer fold 的 train 内部 fit-only/group-OOF 过程生成，不能用 dev/outer-eval gold 标签构造，也不能让同一 dialogue 同时出现在 inner fit/predict；
8. 至少运行 seeds `17,29,43,71,101`；每种正式变体形成 5 folds × 5 seeds 的完整 roster；
9. 完成 current-only、all-history/合理强基线、容量匹配 no-affect-theory、分别 no-VAD/no-inertia/no-transition/no-recovery/no-cross-modal-conflict、`phi` only-to-relation、`phi` only-to-gate、no-history-3×3、forward-only utility、joint-only utility、single-level gate 等预注册对照；
10. 报告 Accuracy、Weighted-F1、Macro-F1、NLL、Brier、ECE、伤害率、CVaR/尾部 regret、风险—覆盖；情绪头/VAD/utility 指标只能作机制诊断，不能替代真实分类成功 Gate；
11. 使用 fold/Session 分组配对统计和 95% CI；不得把独立 query 行当独立实验单位；
12. dev 只用于冻结规则内的 best/reference 选择，不访问该折 outer-eval；各折 Projector、状态 producer、`phi_k`、效用监督和训练状态严格隔离。

I8 的成功 Gate、主对比、效应方向、CI/重采样算法、多重比较处理、失败 run 规则、VAD 来源/prototype 和跨说话人变量语义必须引用新 IEMOCAP protocol/config 的版本与 SHA；未冻结时状态为 `I8_BLOCKED_PROTOCOL_NOT_FROZEN` 或 `I8_BLOCKED_VAD_SOURCE_NOT_FROZEN`，不得由 AI 看过 dev 后补选。配对推断以同一 utterance/dialogue 的方法差为基础，按 dialogue 聚类并按 outer fold/Session 分层，跨 seeds 使用共享重采样索引；不得仅用五个 fold 均值冒充稳定的 95% CI。

PASS：`e→z→预测状态/VAD→phi_k→逐候选3×3/效用/两级门控` 每条连接均有 forward 干预测试、梯度/消融证据和 lineage；group-OOF 覆盖完整且 dialogue overlap 为 0；机制、监督、5 seeds、统计和回退均有 receipt；所有 `(fold_id, role=outer_eval)` label/metric access 为 0；结果边界明确。

FAIL：原始 `x`/gold label 旁路进入 N3、Projector 或状态头跨折共享、train 后验不是 group-OOF、`phi_k` 只计算不进入三处模块、仍使用聚合历史、伪造 utility/VAD target、只跑一个 seed、缺关键消融、跨折状态污染、outer-eval 回流调参，或仅凭 Phase A 结果声称理论创新成立。

Gate 结束创建不可覆盖的 `STOP_BEFORE_TEST` marker，并停止。输出：Phase B 私有 checkpoints、dev 聚合报告、完整 freeze bundle。

## 7. 五折 outer-eval 与 OOF 汇总的独立授权流程

默认 AI **不得继续执行本节**。只有用户或指定负责人在 I8 后另行明确说“授权 IEMOCAP 五折 outer-eval 与 OOF 汇总”，并提供/批准冻结包，才允许开始。这是交叉验证的最终评估阶段，不得描述为全局从未观察的官方 test。

授权前冻结包至少包含：

- clean source commit/tree 与源码快照 SHA；
- IEMOCAP 协议、四分类、五折、统计和 outer-eval runner 配置 SHA；
- aggregate data manifest、Qwen hidden manifest 与 weights manifest SHA；
- 5 folds × 5 seeds × 变体的精确 checkpoint roster；
- 环境/解码器 receipt；
- 指标、比较、CI、汇报模板；
- 不存在的 write-once OOF 输出目标；
- 明确授权 receipt。

正式 outer-eval 必须：

1. 在任何 outer-eval label/metric 访问前验证全部哈希和 `STOP_BEFORE_TEST`，并由 custodian 原子创建不可删除的 durable attempt marker；marker 已存在则拒绝新 attempt；
2. 按冻结映射批量执行五个 `(fold_id, role=outer_eval)`，每个 Session 恰形成一次 OOF 预测；
3. 不在每折结束时把结果返回给开发者用于修改后续折；
4. 所有折完成后一次性发布聚合结果；
5. 输出目录 write-once，存在即拒绝覆盖；
6. 无论正负结果都报告；
7. outer-eval 后禁止修改模型、阈值、标签映射、消融或 claim family；
8. 只公开 aggregate-only 指标，不公开逐样本预测、标签、ID、路径或媒体。

任何中途失败必须保留 marker 和失败状态，由独立审计决定后续处理；执行者不得自行删除输出目录重跑。必须分别记录 `outer_media_access_count`、`outer_feature_access_count`、`outer_label_access_count` 和 `outer_metric_access_count`，不能用单个模糊的 `test_accessed` 掩盖开发期允许的无标签预处理与禁止的标签/指标访问。

## 12. 完成判定

只有满足以下全部条件，才能把状态从“数据完整性 PASS、尚未训练”更新为“IEMOCAP Phase A/Phase B 开发完成、等待 outer-eval 授权”：

- I0–I8 全部 PASS；
- 新 IEMOCAP 专用协议、实现和测试已经进入可追溯 commit；
- 四分类、五折、时间戳视频、K=3/masks 和原始 `x→Qwen e` 三路均有独立审计证据；
- 每折 Projector 独立且仅以 fold-train 更新，`e→z` 边界、Qwen 冻结和无跨折状态复用均有证据；
- Phase B 的情绪后验/VAD 对 train 为 dialogue-group-OOF、对 dev 为 frozen full-train producer；`phi_k` 不含 gold/未来信息并真实连接 3×3、效用与两级门控；
- Phase A 与 Phase B 结果严格分开；
- 五折×至少 5 seeds 和消融 roster 完整；
- 所有 `(fold_id, role=outer_eval)` label/metric access 仍为 0；无标签媒体/feature 访问按独立计数如实记录；
- `STOP_BEFORE_TEST` 已创建并绑定完整 freeze bundle；
- 所有公开工件满足 aggregate-only 和许可边界。

在此之前，任何“已经完成 IEMOCAP 外层五折评估”“模型已在 IEMOCAP 上证明有效”或“可以直接跑 outer-eval”的表述都不成立。outer-eval 完成后只能报告外层 Session 五折交叉验证结论；如需全局从未观察的确认，必须按第 1 节的互斥替代路线另取独立数据。
