### 3.2 标签顺序

最新 MELD 管线固定七类及索引：

```text
0 neutral
1 surprise
2 fear
3 sadness
4 joy
5 disgust
6 anger
```

CSV 中必须且只能出现这七个小写规范名。任何配置、cache、checkpoint、指标文件中的标签顺序必须完全一致；不得沿用 `模型/configs/n3_train_v1.json` 中不同顺序而静默重排。

### 3.3 样本主键和严格历史

样本主键固定为 `(split, Dialogue_ID, Utterance_ID)`，媒体文件需与 `dia{Dialogue_ID}_utt{Utterance_ID}` 一一对应。

本执行单将最新 `K=3` 具体化为：

- 只在同一 split、同一 dialogue 内查找候选；
- 候选必须满足 `history.Utterance_ID < current.Utterance_ID`；
- 按 `Utterance_ID` 由近到远选最近 3 条；
- 不限制候选必须与当前说话人相同，并为每个候选保存 `same_speaker`；这样 Phase B 的说话人关系变量不是常量；
- 不足 3 条时用 mask 表达，不复制样本、不补伪历史；
- 没有历史时精确回退 independent current-only；
- 历史候选标签永远不是模型输入。

固定接口：

```text
current_modalities:       T/A/V current features
history_modalities:       [B, K=3, modality=3, ...]
current_modality_mask:    bool [B, 3]
history_mask:             bool [B, 3]
history_modality_mask:    bool [B, 3, 3]
history_sample_ids:       private audit only; [B, 3]
same_speaker:             bool [B, 3]
```

## 6. G1 — 最新代码实现 Gate 与单样本 Qwen 三模态证明

### 6.1 必须先实现的组件

状态：**全部待实现。** 推荐接口名称仅用于统一协作，不代表文件已经存在：

| 拟议组件 | 必须实现的职责 |
|---|---|
| `extract_meld_qwen_omni_features.py` | 本地冻结 Qwen 对 T/A/V 分别提特征、分片恢复、写三路 cache/provenance |
| `meld_phase_a_dataset.py` | 从私有 manifest/cache 构造 K=3、三类 mask、current-only fallback |
| `train_meld_phase_a.py` | 32/8 smoke 与全量 emotion-only train+dev；按 Weighted-F1 保存 best |
| `meld_phase_a_config_v1.json` | 冻结数据、模型、损失、优化器、选择指标和 test-deny 合同 |

不得假定通用 `AutoModel` 调用就能正确取得 Qwen3-Omni 的三模态隐藏表示。实现时必须以服务器实际安装的官方 Qwen3-Omni processor/model 类为准，并用真实单样本测试证明输出来源。若当前依赖版本不支持该模型，状态为 `G1_BLOCKED_DEPENDENCY`，先修复环境并固定版本，不能退回颜色统计、librosa 手工统计或其它模型后仍称“Qwen 三模态”。

### 6.2 冻结的特征合同

- 模型：本地 `Qwen/Qwen3-Omni-30B-A3B-Instruct`；
- 权重：冻结、`eval()`、`requires_grad=false`、推理在 `no_grad/inference_mode` 下执行；
- 文本、音频、视频必须是三个**独立调用和独立输出**；不得只保存一次三模态混合表示；
- 文本输入只包含当前话语文本；音频输入只包含当前话语音频；视频输入只包含当前话语视频/冻结帧采样；
- 每个话语只提取一次 T/A/V，历史通过 sample ID 引用同一 cache，不重复编码；
- pooling 层、token/frame/time pooling 规则必须在提取前冻结并写入配置；
- 每路 cache 的 sample 顺序、shape、dtype、模型 ID、权重/文件 manifest hash、processor 类与版本、预处理参数、源码 commit 和配置 SHA 必须可审计；
- 最终训练前将三路隐藏表示分别交给可训练 `ModalityProjector → d_model=128`；
- cache 建议使用 `safetensors` 或 `allow_pickle=False` 的分片 NPZ，禁止任意 pickle；
- 恢复时逐 shard 校验配置 identity、sample order hash 和内容 hash；不允许把不同模型/预处理的 shard 拼在一起。

### 6.3 单样本证明

4. 再相同，选择更早 epoch。

| `G3_FAIL_AUDIT` | 全量缺失、全零、NaN、维度、重复或错位非零 | 修复首个根因，使用新 run ID 重新提取受影响模态 |
| `G4_FAIL_TRAIN` | loss 非 finite、best 规则错误、checkpoint 不可恢复 | 作废训练 run，修复并从冻结输入重跑 G4 |
| `STOP_BEFORE_TEST_A` | Phase A train+dev 合格且 test 封存 | 只允许进入 B0 实现/合同审计，不授权 test |
| `B0_FAIL`–`B3_FAIL` | Phase B 实现、监督、冒烟或完整矩阵未通过 | 只修复对应 Phase B Gate，test 继续封存 |
| `B4_BLOCKED_PROTOCOL_NOT_FROZEN` | Phase B 统计/成功 Gate 尚未预注册 | 先提交并冻结 protocol amendment，不得由 AI 临场选择 |
| `PROTOCOL_VIOLATION_TEST_ACCESSED` | 任意开发阶段读取 test | 整轮作废并如实报告，不得继续或引用结果 |
| `STOP_BEFORE_TEST` | Phase B B0–B4 全部合格且 test 封存 | 停止，等待独立冻结审计与授权 |

## 16. GitHub 提交边界

允许提交：

- 新的 manifest/extractor/dataset/trainer 代码；
- 冻结配置；
- synthetic 与不含原始样本的合同测试；
- aggregate-only manifest、计数、hash 和安全指标；
- 本执行单和后续修订说明。

禁止提交：

- MELD 压缩包、CSV、原始文本、标签、音频、视频；
- 私有逐样本 manifest；
- Qwen 权重；
- T/A/V feature cache；
- checkpoint、逐样本预测和含原文日志；
- 服务器地址、绝对数据路径、用户名、密码、token、Cookie、私钥。

提交前只对**明确列入本轮范围的 staged files**做 allowlist 和 staged-diff 扫描；不要用覆盖整个历史仓库的宽泛 secret grep 来替代范围确认：

```bash
git status --short
git diff --check
git diff --cached --name-only

# 人工建立并复核 STAGED_ALLOWLIST；下面只示意比较，不要照抄占位符。
comm -3 \
  <(printf '%s\n' "${STAGED_ALLOWLIST[@]}" | LC_ALL=C sort) \
  <(git diff --cached --name-only | LC_ALL=C sort)

# 只扫描将要提交的文本 diff；命中后逐项人工判断并清除真实敏感值。
git diff --cached --no-ext-diff --unified=0 -- \
  "${STAGED_ALLOWLIST[@]}" |
  grep -nE '^\+.*(password|passwd|secret|token|BEGIN [A-Z ]*PRIVATE KEY|ssh-rsa|https?://[^ ]+@|/(root|home)/|[A-Za-z]:\\Users\\)' || true
```

只有代码、配置、测试和公开安全产物进入 Git。私有数据、特征和训练产物继续留在仓库外。

## 17. 本轮执行的终点

当前服务器 AI 的完整默认终点不是“把 MELD test 跑出一个分数”，而是：

```text
G0 PASS
G1 PASS
G2 PASS
G3 PASS
G4 PASS
PHASE_A_TRAIN_DEV_COMPLETE
STOP_BEFORE_TEST_A
B0 PASS
B1 PASS
B2 PASS
B3 PASS
B4 PASS
PHASE_B_TRAIN_DEV_COMPLETE
STOP_BEFORE_TEST
test_accessed=false
```

若本次委托只覆盖 Phase A，则在 `STOP_BEFORE_TEST_A` 停止并汇报；不得据此运行 test。若委托明确覆盖完整方案，则继续 B0–B4，最终在 `STOP_BEFORE_TEST` 停止。到达相应停止点后，只提交最新实现、配置、测试和 aggregate-only 审计产物并等待独立审查；正式 test 不能由本轮流程自动触发。
